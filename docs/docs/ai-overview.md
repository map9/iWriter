# AI 总览

> 适用版本：iWriter `0.1.24`
>
> 最后更新：2026-07-27

## 两种模式

### Edit

- 面向文档编辑与改写。
- 支持 proposal/HITL 审批流。
- 适合润色、续写、重写、局部修订、结构调整等“先提案后落地”场景。

### Creative

- 面向长线小说创作，以工作区中的纯 Markdown 文件管理项目、世界观、人物、提纲、正文、素材、评审与风格。
- 支持创意与提纲、正文撰写、精修、跨章重构、小说导入和风格蒸馏等任务。
- 主 Agent 负责理解目标和编排流程，Writer 专门写正文，Reviewer 只读评审；复杂研究或导入分析由通用子 Agent 承担。
- 正文写作采用“确认写作意图 → 写作会话内累积 → 整章差异确认”的闭环，支持接受、反馈返工或拒绝回滚。
- 适合需要项目级设定、三层提纲、角色弧光、跨章节一致性和 Git 版本管理的小说项目。

## 会话与上下文

- 支持会话线程历史。
- 支持附加文本、目录、图片、PDF 等上下文。
- 提供上下文 token 统计、自动摘要阈值进度和长会话自动压缩。
- 上下文圆环是只读进度指示器；提示中会显示自动摘要阈值、本次会话的真实 token 用量、缓存命中，以及 Creative 模式下子 Agent 的输入 / 输出统计。
- 会话达到阈值后由 DeepAgents 自动生成摘要；当前不提供手动压缩入口。
- Provider 可配置备用模型；主模型持续失败并成功切换时，界面会显示提示。

## 当前实现边界

- `Edit` 模式不会直接无确认改写正文，仍然以提案审批为主。
- `Creative` 面向长线创作，不适合无项目结构的一键生成；正式对象变更与写作会话都需要作者审批。
- AI 会按需读取当前任务所需对象，不会在每次会话启动时扫描整个工作区或自动重建项目摘要。
