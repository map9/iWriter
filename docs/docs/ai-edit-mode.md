# AI Edit 模式与审批流

> 适用版本：iWriter `0.1.20`
>
> 最后更新：2026-06-17

## 流程图

```text
用户提出编辑目标
  -> AI 读取上下文并生成提案
  -> 用户逐项决策（approve / edit / reject）
  -> 仅已通过提案写入文档
  -> 用户保存
```

## 三种决策

- `approve`：接受该提案
- `edit`：手动修改提案后再执行
- `reject`：拒绝该提案，不写入

## 安全边界

- 不会在未审批情况下直接写盘。
- 提案机制用于降低误改风险。
- 新建文件、覆盖文件、删除文件等文件系统变更会进入单独的审批卡片，确认后才会落地。
- 当同一轮中同时出现文档编辑和文件系统操作时，iWriter 会拆分可审阅项目，避免不同类型的操作互相吞掉审批状态。

## 可用工具范围

Edit 模式可以读取当前文档结构、按章节或块读取内容，并对指定块执行插入、替换、删除等编辑动作。它也可以在需要时读取本地 PDF 页面、抓取网页内容或使用已配置的 Web Search Provider 检索资料。

图片写入会尽量保持 Markdown 图片语法与段落空行稳定；创建新文档时会先展示预览，审批通过后再写入工作区。

## 失败与回退

- 网络或 Provider 异常时，提案可能生成失败。
- 如果模型不支持工具调用、结构化输出或上下文长度不足，可能需要在 Provider 设置中切换模型或补充模型能力配置。
- 可调整提示词后重试，或先手动编辑再继续 AI 协作。
