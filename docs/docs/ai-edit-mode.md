# AI Edit 模式与审批流

> 适用版本：iWriter `0.1.22`
>
> 最后更新：2026-06-30

## 流程图

```text
用户提出编辑目标
  -> AI 读取上下文并生成提案
  -> 用户逐项决策（approve / edit / reject）
  -> 仅已通过提案写入文档
  -> 用户保存
```

## 三种决策

- `approve`：接受该提案
- `edit`：手动修改提案后再执行
- `reject`：拒绝该提案，不写入

当一轮包含多条建议时，可以用左右箭头逐条查看，并对当前建议选择接受、修改后接受或拒绝。也可以使用“全部接受”或“全部拒绝”一次处理整批建议。

> “全部接受 / 全部拒绝”会覆盖这一批中已经做出的逐项决定，然后立即提交整轮审核。若希望保留逐项决定，请继续逐条处理。

块级编辑建议提供“定位原文”按钮：

- 建议来自当前或已打开文档时，会切换到对应标签页并高亮原文。
- 建议来自尚未打开的本地文档时，会先打开目标文档，等待内容加载后再定位。
- 未保存文档只有在对应标签页仍存在时才能定位。
- 如果目标文档或原文块已不存在，iWriter 会提示无法定位；这不会自动接受或拒绝该建议。

## 安全边界

- 不会在未审批情况下直接写盘。
- 提案机制用于降低误改风险。
- 新建文件、覆盖文件、删除文件等文件系统变更会进入单独的审批卡片，确认后才会落地。
- 同一轮包含多个文件操作时，可以逐项检查，也可以整批接受或拒绝；删除文件 / 目录会显示高风险提示，目录删除会同时移除其中全部内容且无法撤销。
- 当同一轮中同时出现文档编辑和文件系统操作时，iWriter 会拆分可审阅项目，避免不同类型的操作互相吞掉审批状态。

## 可用工具范围

Edit 模式可以读取当前文档结构、按章节或块读取内容，并对指定块执行插入、替换、删除等编辑动作。它也可以在需要时读取本地 PDF 页面、抓取网页内容或使用已配置的 Web Search Provider 检索资料。

图片写入会尽量保持 Markdown 图片语法与段落空行稳定；创建新文档时会先展示预览，审批通过后再写入工作区。

## 失败与回退

- 网络或 Provider 异常时，提案可能生成失败。
- 如果模型不支持工具调用、结构化输出或上下文长度不足，可能需要在 Provider 设置中切换模型或补充模型能力配置。
- 可调整提示词后重试，或先手动编辑再继续 AI 协作。
