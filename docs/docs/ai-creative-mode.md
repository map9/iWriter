# AI Creative 模式：小说创作指南

> 适用版本：iWriter `0.1.18`
>
> 最后更新：2026-06-15

## 这是什么

Creative 模式是 iWriter 的小说创作智能体。它不是一个"帮你一键生成文章"的写作工具，而是一个创作伙伴：你决定方向，它帮你规划、起草、维护设定一致性、拓展创意可能性。

整个写作过程只有两样东西需要你关注：**文稿**和**对话**。

---

## 开始使用前

**必须先打开工作区**（Open Folder），Creative 模式需要一个本地文件夹作为项目根目录。没有打开工作区时，AI 面板中的 Creative 选项会变灰不可点击。

打开工作区后，切换 AI 面板右上角的模式选择器为 **Creative**，然后直接开始对话即可。

你不需要手动创建任何文件。第一次和 agent 对话时，它会自动在工作区根目录生成：

- `storybible.md`：agent 维护的项目理解摘要
- `draft/`：存放章节文件和碎片的目录

---

## 核心概念：StoryBible

**StoryBible** 是 agent 对当前项目状态的理解摘要，不是你填写的表单。它由 agent 在对话和写作过程中自动维护，包含：

- **Premise**：一句话核心前提——这个故事写的是谁的什么变化
- **Theme**：主题——你想让读者带走的问题、情感或价值命题
- **Promise to Reader**：读者承诺——开篇给读者许诺的基调与体验
- **角色**：每个已出现角色的心理三角（核心欲望 / 核心恐惧 / 虚假信念）、声音特征、当前弧光阶段
- **世界观**：已确立的规则、时间线关键事件、禁区
- **故事状态**：当前推进到哪里、已埋下的伏笔、开放的冲突线索
- **写作约束**：叙事视角、时态、基调、风格
- **待解决**：agent 发现的矛盾、作者尚未确定的问题

新项目启动时，agent 会在建立角色之前先引导你填写 Premise、Theme 和 Promise to Reader。如果这三项为空，每次会话启动时 agent 都会提醒。

你随时可以在编辑器里直接打开和修改 `storybible.md`。你的修改优先级高于 agent 的理解。

## 基本工作流

### 1. 从任意起点开始

你不需要准备好完整的设定才能开始。任何起点都可以：

- 一句话：「我想写一个关于失业音乐人的故事」
- 一个场景：「A 在地铁上发现了一封不是写给他的信」
- 一个问题：「如果 B 在这里说了真话会怎样」
- 几个散乱片段

### 2. 会话启动：agent 先看变化

每次打开对话，agent 会先执行一个启动序列：

1. 检查上次会话后文稿有没有变化（你是否直接编辑了文件）
2. 读取当前 StoryBible
3. 如果发现变化，读取相关文件并更新 StoryBible
4. 再回应你

这意味着你不需要每次重新解释情况——agent 会自己找回状态。

### 3. 探索模式 vs 写作模式

**探索信号**：你在分享想法、讨论方向、问「你怎么看」、质疑已有设定

此时 agent 会保持在探索状态，给出 2-3 个发散方向或一个尖锐的问题，不会直接推进到写作。

**写作信号**：你说「帮我写」、「起草」、「写这个场景」

此时 agent 进入写作流程：读上下文 → 给 plan → 等你确认 → 写作 → 做一致性检查。

---

## Plan-first 机制：写之前先说打算

对于新场景、新章节、超过一段的改写，或涉及已有设定的修改，agent 会先提出写作计划请你确认，而不是直接开始写。

**Plan 包含什么**：
- 打算写什么（场景、情节、情绪弧）
- 采用的叙事视角
- 情绪转折点
- 核心冲突
- 为什么这样写符合故事走向
- **依据 StoryBible 的具体约束**（agent 必须显式引用）

**如果 plan 与 StoryBible 有偏差**，plan 中会出现 **⚠ 偏离声明**，说明偏离了哪条设定、理由是什么。

**你的选择**：
- `approve`：接受 plan，agent 开始写作
- `edit`：直接修改 plan 内容，修改后的版本是执行约束
- `reject`：拒绝，agent 不会继续，你可以给出新方向

> **小改动**（单段润色、对话调整、碎片记录）不需要 plan，可以直接进行。

## 创意方向卡片（AdvisorAgent）

当 agent 发现你给出的写作方向还有更好的角度未被挖掘时，它会在 plan 前主动插入一组**创意方向卡片**：

```
╔════════════════════════════════════╗
│  3 个创意方向                       │
├────────────────────────────────────┤
│ [人物] A 用沉默回应 B 的质问，但     │
│       内心记录了每一句话            │
│       · StoryBible 里 A 的压抑特质  │
│         从未在对话中被利用过         │
│                                    │
│ [情节] B 的信息优势在这场对话中意外  │
│       失效，反而暴露了弱点          │
│       · 目前 B 一直处于强势位，读    │
│         者需要看到他有软肋          │
│                                    │
│ [结构] 将冲突推迟到章末，用外部事件  │
│       强制两人进入同一空间          │
│       · 直接对话太提前消耗了情感资本 │
╚════════════════════════════════════╝
```

每张卡片有：**类型标签**（情节 / 人物 / 结构 / 场景 / 主题）、**方向描述**（一句话，读者层面的体验）、**角度说明**（灰色小字，这个方向用到了哪个未被开发的故事元素）。

**你可以**：
- 选择其中一个方向，告诉 agent「用第二个方向」
- 忽略所有方向，直接说「继续按我的方向」
- 方向卡片不阻塞流程，不需要审批

你也可以主动触发创意建议：告诉 agent「我不知道接下来怎么写」或「给我几个想法」，agent 会调用创意分析工具给出方向。

## 一致性检查卡片（ConsistencyAgent）

每次 agent 写完并经你审批落地之后，它会自动做一次一致性检查，结果以卡片形式出现在对话里：

```
╔════════════════════════════════════╗
│  2 条一致性建议                      │
├────────────────────────────────────┤
│ [视角] [轻微]  draft/ch03.md::第三段 │
│ 叙述知道了视角人物不应知道的信息。   │
│ 建议：改为感官推断或移到对话中。      │
│                                    │
│ [人物] [提示]  draft/ch03.md::结尾  │
│ A 的这处内心描写稍微直白，与"压抑    │
│ 的骄傲者"设定略有偏离。              │
│ 建议：用行为替代心理描写。           │
╚════════════════════════════════════╝
```

卡片颜色：
- 蓝色（提示）：信息性观察，可忽略
- 黄色（轻微）：建议调整但不紧急
- 红色（重要）：视角越界、时间线矛盾等需要关注的问题

除常规检查外，ConsistencyAgent 还会检测两类跨章节问题：

- **伏笔审计**：识别早期已植入但在当前章节前后仍未回收的伏笔，提示是否有角色意外获取了本应保密的信息
- **弧光推进检查**：比较当前章节与前一章节中角色的心理状态——连续两章无实质弧光推进会标记为轻微问题，心理状态突变但缺乏铺垫会标记为重要问题

**一致性检查不阻塞写作**。你可以选择处理建议，也可以继续下一段，之后再回来修。

## 叙事方向探索

当你站在故事的分叉点，不确定该走哪条路时，可以让 agent 替你把每个方向"试着走一遍"——不是空想，而是真正草拟出来。

触发方式：告诉 agent「我想看看两种结局走向」或「帮我探索这个场景的不同可能性」。

agent 会先和你确认：

1. **分叉点**：从哪一段/哪一章开始分叉
2. **方向列表**：2–3 个方向，每个用一句话描述（如「A 选择离开」vs「A 选择留下揭发」）

确认后，agent 为每个方向各自草拟一份探索稿（约 300–500 字的关键场景），然后以**对比卡片**的形式呈现：

- 每个方向的叙事特征（基调 / 节奏 / 情感走向）
- 对后续故事线的影响（什么可能性被打开，什么被关闭）
- 工艺注记（节奏、主题共鸣）

**agent 不会评判哪个方向更好**，只描述差异。

选定方向后，你可以审批一个**融合提案**，查看现有草稿与探索稿的对比，确认后 agent 将探索内容写入对应章节。也可以放弃全部探索，不影响任何已有草稿。

探索草稿保存在工作区 `.iwriter/explorations/` 目录，不会写入 `draft/`，除非你明确批准融合。

## Git 版本控制

如果你的工作区已经初始化了 git 仓库（`git init`），agent 会在关键节点主动提议版本快照。

**自然检查点**：

- 一章草稿审批完成 → agent 提议 `git_commit`，提交信息由 agent 起草，你可以编辑或拒绝
- StoryBible 重建或重大结构调整 → 同上
- 叙事里程碑（弧线收尾、故事中点）→ agent 提议打 `git_tag` 标记

所有 git 操作都需要你明确审批，**agent 不会静默执行任何 git 命令**。

如果工作区没有 git 仓库，git 工具不会出现在 agent 的工具集中。

## 章节管理

你可以通过对话让 agent 管理章节文件，无需手动重命名文件：

- **创建章节**：「在第二章后面新增一章」→ agent 提议文件名并自动重编号
- **删除章节**：「删除第三章」→ agent 提议并显示对后续编号的影响，确认后执行
- **重命名**：「把 ch03 重命名为 ch03-转折.md」
- **重排顺序**：「把第四章移到第二章的位置」→ 一次性重排所有受影响章节

所有操作均需审批，支持自动级联重编号，操作前可查看 before/after 文件列表。

## 角色设定：心理三角

当你介绍一个新角色时，agent 会在将角色写入 StoryBible 前先读取「角色复杂度」写作技法，为这个角色建立**心理三角**：

- **核心欲望**：表层目标背后真正驱动行为的东西
- **核心恐惧**：他最不能承受的失去
- **虚假信念**：他对世界或自己的一个错误认知，这是弧光的根基

这三项会直接写入 StoryBible，而不是「内向、聪明、有能力」这类标签。这是角色在后续写作中能从内部生长出行为的基础。

## 故事架构分析

当你想了解整体进展时，可以问：

- 「故事现在在哪个阶段？」
- 「节奏有没有问题？」
- 「整体架构怎么样？」

agent 会调用故事架构分析工具，返回：
- 各章节摘要与字数
- 当前张力曲线位置
- 结构健康状况（是否有松弛段、开头力量、高潮节奏）
- 主题线索分析

## 约束与安全边界

- **agent 只通过工具写文件**，不会绕过你直接改文稿
- 需要明确审批的操作：写章节（`write_to_chapter`）、替换 StoryBible（`replace_storybible_section`、`rebuild_storybible`）、章节增删重排、探索方向融合（`promote_exploration`）、StoryBible 压缩、所有 git 操作
- 不需要审批的操作：碎片记录（`add_fragment`）、读取文件、查看 git 状态和历史
- **探索草稿不会自动写入 draft/**：叙事方向探索的临时草稿只保存在 `.iwriter/explorations/`，除非你明确批准融合
- **git 操作全部需要批准**：agent 不会静默提交或打标，commit message 可以在审批时修改
- **作者判断优先于一切**：任何时候你说「不，换个方向」，agent 立刻跟随，不解释之前的选择
- 如果你的最新意图与 StoryBible 中已确立的设定冲突，agent 会显式指出冲突并等你裁决，不会静默选择

## 常见问题

**Q：我能不能直接修改 storybible.md 和 draft/ 下的文件？**

可以，随时都行。agent 每次会话启动时会检测文件变化，并在对话中反映你的修改。你的直接编辑优先于 agent 的理解。

**Q：agent 忘记了之前说的设定怎么办？**

检查 `storybible.md` 里是否包含了那条设定。如果没有，让 agent 「把 X 加到 StoryBible」；如果有但被忽略了，可以直接说「你忽略了 StoryBible 里 A 的性格，请重新看一下」。

**Q：能不能跳过 plan 直接写？**

可以，对于短段落和碎片，直接说「帮我在 fragments.md 里记下这个想法」就不走 plan 流程。但对于新章节和超过一段的改写，plan-first 是内置的，这是为了避免"写了又全改"的浪费。

**Q：一致性检查有时候不准确怎么办？**

一致性检查是建议，不是约束。你可以直接忽略不认可的建议，继续写。如果某类建议持续不准，可以在 StoryBible 的「写作约束」部分明确说明你的写作选择（比如「允许部分视角越界，这是刻意的叙事选择」）。

**Q：故事写到一半，StoryBible 越来越长怎么办？**

agent 有两条路可以处理：

- **StoryBible 压缩**（推荐）：当 StoryBible 超过阈值时，agent 会在会话启动时主动建议，将你认为已完成的章节归档为简短摘要，追加到 Story State 的归档区。不删除任何现有内容，归档后上下文窗口更充裕。审批时可以查看将要追加的摘要内容。

- **全量重建**（`rebuild_storybible`）：重读所有草稿，重新压缩并重写整个 StoryBible。适合设定发生重大调整后需要彻底刷新的情况。同样需要明确批准。

如果你打了 git tag 标记了里程碑，agent 还会顺带建议把该 tag 之前的章节一起归档。
