# Git 文档版本管理

> 适用版本：iWriter `0.2.1`
>
> 最后更新：2026-07-28

iWriter 使用标准 Git 为笔记、文稿和小说项目提供文档版本管理。仓库仍是普通 `.git` 目录，可以继续与命令行、GitHub、GitLab 或其他 Git 客户端配合使用。

## 使用前提

- 系统需要安装 Git。
- 当前版本以工作区根目录作为仓库根，一次管理一个仓库。
- HTTPS 凭证使用系统 Git credential helper，SSH 使用系统 ssh-agent；iWriter 不保存远程仓库密码。

打开左侧“文档版本管理”面板后：

- 非 Git 工作区可以选择初始化仓库。
- 也可以输入远程 URL，将仓库克隆到本地目录后作为新工作区打开。
- 未检测到 Git 时，面板会提供安装说明、下载入口和重新检测操作。

## 查看与组织变更

变更按以下状态分组：

- Merge Changes：存在冲突、等待解决的文件
- Staged Changes：已加入暂存区的文件
- Changes：已跟踪但尚未暂存的修改
- Untracked：尚未被 Git 跟踪的文件

列表支持平铺和目录树两种视图。Explorer 会显示文件 Git 状态，目录节点显示子树中最高优先级的状态颜色；状态栏显示当前分支、领先 / 落后、同步进度和变更数量。

点击文件会打开 Diff 标签页。右键菜单还可打开原文件、在系统文件管理器中定位，或将未跟踪文件加入 `.gitignore`。

## 暂存、放弃与提交

可以对单个文件、整个目录或整个分组执行：

- Stage / Unstage
- Discard
- Add to `.gitignore`

文本 Diff 还支持对单个 hunk 暂存、取消暂存或放弃。放弃更改、删除未跟踪文件等不可逆操作会要求确认。

提交区支持：

- Commit：提交已暂存内容
- Commit All：暂存所有变更后提交，包括未跟踪文件
- Amend：修订上次提交
- Undo Last Commit：撤销最近一次提交并保留工作区内容

未暂存任何内容时，主提交按钮的行为可在“偏好设置 → 文档版本管理”中设置为：

- 提交所有更改
- 禁用，要求先暂存
- 每次询问

## Diff 与冲突合并

Diff 作为普通编辑区标签页打开，支持：

- Split / Inline 两种布局
- 行号、差异概览、上一处 / 下一处差异
- 查看未暂存、已暂存和历史提交中的文本差异
- 对未暂存的 Markdown / 文本源直接编辑并保存
- 对单个 hunk 执行 Git 操作

`.iwt`、JSON 和二进制内容在 Diff 中保持只读。文件在 Diff 打开后若被外部修改，保存会被拒绝并提示重新载入，避免覆盖较新的磁盘内容。

发生合并冲突时，文件进入 Merge Changes。合并标签页上方显示 ours / theirs 对照，下方是可编辑结果；可以逐块采用当前版本、传入版本或两者。保存结果并暂存后，文件会离开冲突分组。

## 分支

仓库菜单支持：

- 创建或重命名分支
- 切换本地 / 远程分支
- 合并分支
- 删除分支
- 发布当前分支并设置 upstream

切换、合并和删除前会先执行预检：

- 切换分支遇到本地更改时，可选择贮藏后切换、迁移更改或放弃后强制切换。
- 非快进合并会提示可能产生合并提交与冲突。
- 删除分支前会检查未推送提交、是否已合并到主分支，以及是否仍被其他本地分支依赖。

## 远程、同步与 Stash

支持添加、删除和查看 remote，并执行：

- Fetch
- Pull
- Push
- Sync
- Publish Branch

Clone、Pull、Push 和 Sync 会在界面与状态栏显示进度。Sync 使用带 autostash 的 Pull：工作区存在未提交变更时会临时贮藏，拉取后再恢复；恢复产生冲突时转入 Merge Changes。

Stash 支持：

- 保存变更，可选择包含未跟踪文件
- Apply / Pop
- 查看和删除 stash

## Graph、Timeline 与 Tags

文档版本管理的 Graph 显示仓库提交历史与分支泳道，可以：

- 查看当前分支或全部分支
- 展开提交查看文件列表 / 目录树
- 打开某个文件在该提交中的 Diff
- 复制提交 hash 或信息
- 从指定提交创建分支或 tag

Explorer 的 Timeline 跟随当前选中文件，显示该文件的历史提交。可以打开历史 Diff，或将单个文件恢复到指定版本。

Tags 支持创建、删除、查看和推送，适合标记初稿、投稿版、出版版等稳定里程碑。

## 安全提醒

- Git 操作直接作用于工作区的真实仓库。
- Discard、强制切换、删除分支、删除 stash 和恢复历史文件可能丢失未保存内容，请先阅读确认框中的影响说明。
- 大范围改稿或跨章重构前，建议先提交或创建 tag。
