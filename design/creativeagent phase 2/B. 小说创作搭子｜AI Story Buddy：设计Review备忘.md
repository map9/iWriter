### R02 写作会话期间作者并发手工编辑语义未定义 —— 已落实（2026-07-06）

> **定案**：方案 A'（code agent 式，参照 Claude Code 的并发语义）——①会话期间作者随时可改，不挂起、不弹窗，编辑器仅显示安静的"AI 写作会话进行中"标识；②agent 每次块级写入做新鲜度校验，作者编辑同样推进快照版本（§2.12 契约补一句），陈旧写入失败 → SA02 重读适应，作者修改是新事实；③终审卡归因明示：检测到非 agent 修改时标注"含手工修改，reject 将一并回退"，reject 需二次确认，保留手工部分的出口是 approve/rework；④作者中断（FR-8.2）= 停止后续动作，已累积写入不自动回滚，留工作树由作者处置。落点：03 §5.3、04.1 §5 设计 5/7。
>
> **落实**：03 §5.3（"作者并发编辑"专条：安静标识、新鲜度校验、终审卡归因 + reject 二次确认；异常恢复条补中断语义）；04.1 §5 设计 5（作者编辑推进快照版本、陈旧写入失败返回新映射）/设计 7（会话期编辑不挂起不加锁、经快照版本对 agent 现形）、§6 会话状态机（终审卡归因转移）。

### R03 S07 重构路径下写作会话的开启信号缺机制 —— 已落实（2026-07-06）

> **定案**：方案 A——授权登记 + 懒激活，单章与重构统一为一个机制：①`confirm_writing_plan` 被 approve 时 host 登记"写作授权"{计划文本, 章节清单}（普通 S05 清单长度 1，S07 重构为多章），host 只依赖这个必然可见的审批事件，不感知 task 委派；②Stage 2 懒激活：块级编辑首次命中授权清单章节时激活该章会话、此刻取基线快照（消除批准到动笔间基线陈旧），放行累积；③一个正文文件至多一个活动会话，跨文件可并存，登记结构 threadId → {授权清单, 活动会话集合}；④前提缺口切回构思时会话保持开启（域外写照常人工审批，无泄漏），不引入挂起态；⑤授权在全部章节终审完成或作者显式取消时结束，进程中断沿用未闭合会话恢复条款。落点：03 §5.3、04.1 §6。

>
> **落实**：03 §2.5 S01（保证机制句）；04.3 §1 S01 题注、§4 A00 红线首条；03 §10.3（勾检项）。

skill 正文按需加载是建议性的，"强制"只能靠 A00 prompt 写死；保证机制未在 04.3 §4 A00 条目显式写明，实测模型可能跳过路由直接干活（红线"不允许因看起来简单跳过"约束不了不读正文的模型）。涉及：03 §2.5、04.3 §1/§4。

### R10 非正文对象的 commit 时点无设计 —— 已落实（2026-07-06）

> **定案**：commit 建议时点从正文侧 2 处扩展为 **5 处**（均为建议非强制，`git_commit` 经 interruptOn）：①整章终审 approve（已内置）；②重构预检批准后动手前（已内置）；③候选晋升为正式对象落地后（晋升审批卡顺带附"建议 commit"勾选）；④大纲/设定/角色对象的确认里程碑（status 转"已确认"、或已确认对象核心字段的批准变更落地后）；⑤S11 初始化完成（首次 commit 固化基线）。配套堵漏：放弃候选 `delete_file` 前若该文件从未被 commit，审批卡显式提示"无 git 历史，删除即永久丢失，建议先 commit"。作者持续拒绝 commit 的退化边界照旧（§9）。
