> StoryForge 是**纯前端 IndexedDB（Dexie）**，无后端。所有表的导出/导入/删项目/删世界组/多世界迁移都由 `PROJECT_TABLES` 派生，不允许手写表清单。

## 读表须知（元信息图例）

每张表在 `PROJECT_TABLES` 登记以下元信息：

| 元信息 | 含义 |
|---|---|
| **owner** | 归属类型：`project`（项目级，随项目删）/`global`（全局，跨项目）/`transient`（临时态）/`blob`（原文二进制）/`direct-child`/`indirect`（经中间表解析归属） |
| **worldScoped** | 有 `worldGroupId`，按世界组隔离/删除（多世界项目） |
| **homeWorldScoped** | 有 `homeWorldGroupId`（角色专用：原属世界，跨世界角色为 null） |
| **exportable** | 是否进 JSON 完整备份。`false` = 可重建派生缓存 / 临时态 / 全局态，不导出 |
| **tree** | 自引用树（`parentId`）；导出用 `_exportId` 重映射 |
| **refs** | 对其它表的引用及删除策略（cascade 级联删 / removeItem 清数组项 / remap 重映射 / 软引用保留） |

通用字段（几乎每表都有，下文字段表中省略）：`id?`(自增主键)、`projectId`、`createdAt`、`updatedAt`（均为 timestamp）。

**表数量说明**：当前 42 张。历史上 `factions`（势力）、`itemSystems`（道具体系）已于 DB v29 并入 `codex` 词条删除；`powerSystems` / `geographies` / `histories` 为旧独立表，语义已并入 `worldviews` / `codex`，作兼容保留。

## 附：数据流中的表角色（对照 D 的四层记忆/软硬分界）

```
上游设定表（读侧结构约束）
  projects · worldviews · storyCores · powerSystems · characters ·
  creativeRules · worldRulesProfiles · codexCategories/Entries · historicalTimeline/Keywords · importantLocations
        │  assembleContext / context-builder 格式化
        ▼
生成产物表（正向链落库）
  outlineNodes → detailedOutlines/emotionBeatCards → chapters(content)
        │  正文写完 → 反写
        ▼
下游记忆/证据表（回流上下文 · 软抽取+硬校验+作者确认）
  chapters(summary/handoff/reconciliation) ·         ← A 章节交接
  narrativeSummaryNodes ·                             ← B 层级摘要（不导出，可重建）
  temporalFacts · itemLedger · stateCards ·           ← C 事实/持有/状态（candidate→canon）
  retrievalChunks ·                                   ← D 原文检索（不导出，可重建）
  storyTimelineEvents · characterRelations · foreshadows · codexEntries · importantLocations
        └───────────────── 回流进 assembleContext ──────────────┘

跨切面：worldGroups/worldGroupLinks（多世界隔离盖章）· references/referenceChunkAnalysis（参考手法注入）·
        userStyleProfiles（文风反哺）· snapshots（版本历史）· promptTemplates/Workflows（提示词库）· aiUsageLog（消耗）
```

**共性规律**：① 设定表是"读侧结构约束"，恒定装配进生成 prompt；② 生成产物表是链条落点；③ 下游记忆/证据表全部走"AI 软抽取 → 确定性硬校验（受控谓词/引文回查/FK/去重/CAS-hash）→ 候选 → 作者确认 → canon"，再回流；④ 可重建的派生缓存（`retrievalChunks` / `narrativeSummaryNodes`）不导出、导入后重建；⑤ 全局态（`promptTemplates/Workflows`）与临时态（`import*` / `snapshots` / `aiUsageLog`）不进项目 JSON 备份。表的生命周期全部由 `PROJECT_TABLES` 一处派生。
