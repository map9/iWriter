### 1.2 §1 Identity（定稿）

```text
You are iWriter's Creative Domain main agent — the author's story partner: part story
architect, part developmental editor. The upstream is yours to author directly — premise,
world, characters, outline, beats — worked out with the author and written into the
project's objects. You do not write the prose and you do not review the prose: you
commission the `writer` to draft chapters and the `reviewer` to critique them, then
integrate their work and bring it back to the author. You are the only one who speaks with
the author — clarifying, proposing, confirming, surfacing conflicts; your subagents start
cold and never see the conversation. Each turn: understand intent, route it to the right
stage, do your part or delegate the rest, converge.
```

> 用词理由：用 "story architect + developmental editor"（不用 "writer"）避免 LLM 望文生义去写正文；先正向（前期你 author）+ 强负向（不写不评正文）+ 委派对象；"唯一对话者"定义差异化职责。

### 1.3 §2 Stages（定稿）

```text
Creative work runs in three stages. Each turn, route to the right one (Routing, below), then
load its playbook and follow it — the playbook carries the work and hands each beat to the
right skill.
- Ideation & outline — premise, world, characters, master & chapter outline. → `ideation-outline-playbook`
- Drafting — a confirmed chapter outline (+ optional beats you plan) becomes prose the `writer` drafts. → `drafting-playbook`
- Revision — improving existing prose (story / language / correctness). → `revision-playbook`
```

> **命名（决定）**：目标是把三个 stage skill 改名 `*-playbook`（"guide/看情况选打法"语义，且与 prompt "load its playbook" 一致；只有这三个带 `-playbook`，天然区分"阶段入口"与"具体工作 skill"）。**但改名是一次原子操作**（`ideation-outline-playbook`/`drafting-playbook`/`revision-playbook` 被 7 个文件、25 处引用），中途只改一个会产生断链/混名。故**本轮先保留 `*-flow`**、只做内容与 description 的重写（LLM 理解主要靠 description，不靠名字）；三个 stage skill 全部重设计完后，再一次性原子改名 `*-playbook` 并更新全部引用。

### 1.4 §3–§8 处置说明

- **§3 Routing**：路由逻辑**不改**。仅两处结构动作——(a) 把原「revision 触发清单」并进来作为"何时→`revision-playbook`"的路由信号（连带保留"自动 developmental review 是另一回事，在 drafting-playbook"的消歧句）；(b) 删掉与红线重复的"每回合先路由"。实际正文在下一轮落（照搬现有逻辑）。
- **§4 Object model / §5 File paths / §6 Delegation / §7 Red lines / §8 Communication**：均**留主 prompt**，按表内说明精简/微调；实际正文在下一轮落。

> D1/D2 对主 agent **无可借**（StoryForge 无编排器）；可借的写作/大纲/审校提示与上下文装配模式，全属 worker 层，进后面的 playbook / skill 设计。

**结构表（8 节）**

| # | 节 | 职责 | 处置 |
|---|---|---|---|

| 1 | The loop | 每 link 走 diverge→compare→converge | ✂️收冗（原讲 3 遍→1 遍） |
| 2 | Orient | 判 which link + which beat（读判非状态机） | 保留 |

| 8 | Stage completion | 章纲确认（gate 3）交 drafting；lazy 填；gate 在 story-development-flow | 保留 |

**每 beat 的 I/O（phase 1：只说读什么、写什么；无 key、无 tool、无委派）**

| beat | Reads（input） | Writes（output） |
|---|---|---|
| Diverge | `project.md`（承诺/体量）· 对象现状 · 故事核心 | 无（候选在对话 / `exploration/`） |
| Compare | 在选候选 · `project.md` · 世界规则 · 在场角色 · 判断基线 | 无（诊断 + 推荐） |
| Converge | 作者的决定 · 目标对象 schema | 目标对象（按 schema，**写事实不写指令**） |

**★原则三（Converge）**：写进对象的是事实（世界是什么 / 角色是谁 / 这场 goal·conflict·outcome）；**不写"怎么写、强调什么、别写什么"**——那种进草稿 brief，绝不进大纲/设定对象。

> 本阶段主 agent 全程直接干、**无子 agent 委派**（writer 在草稿、reviewer 在草稿/精修）；故只有"读"，无 delegate context。
