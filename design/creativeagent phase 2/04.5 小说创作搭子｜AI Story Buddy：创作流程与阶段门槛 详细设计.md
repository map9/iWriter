# 小说创作搭子｜AI Story Buddy：创作流程与阶段门槛 详细设计

> 本文档补齐《03 概要设计》缺失的**过程模型**：默认创作流程（阶段序列与产物）、每次阶段跃迁的**就绪门槛**（进入下一阶段的前置条件）、门槛与作者自主性的和解原则，以及流程状态的持久表示 `.iwriter/status.md`。设计原则、对象 schema、技能树见 03 / 04.2 / 04.3；**本文中的 §x 如无特别说明均指《03 概要设计》。**

* * *

## 0. 为什么需要本设计

本系统**不用 graph 强制状态机**控制创作流程——这是有意的：作者可以任意进入、反复、跳跃（FR-2.5 显式指定优先）。代价是：**如果 prompt 与 skills 不写明"每个阶段跃迁的前置条件"，流程就完全交给模型即兴，产出物质量不可控。**

实证（`new01` 工作区）：总纲仍是 `草稿中`、且**完全没有章纲**的情况下，模型直接写出了 `manuscript/ch001.md`——beat 是从事件级总纲的散点提示里硬凑的，不是从场景三段式（目标/冲突/结果）长出来的。写作者不可能在不知道场景目标/冲突/结果时写好一场戏。

本设计补上三件事，在"不锁死流程"与"质量可控"之间取平衡：
1. **默认创作流程**（阶段序列、产物、执行体、完成标志）；
2. **阶段门槛**（进入下一阶段的就绪判据，按创作逻辑给出）；
3. **门槛的软硬原则**（提醒非硬锁）+ **流程状态的持久表示**（status.md）。

## 1. 默认创作流程（阶段 · 产物 · 执行体 · 完成标志）

| 阶段 | 产物对象 | 执行体（技能） | 完成标志 |
| --- | --- | --- | --- |
| 立项 | `project.md` | A00（S11 project-bootstrap） | premise 四要素成立 + 主题 + 篇幅规划 |
| 设定/角色 | `worldbuilding/*.md`、`characters/*.md` | A00（S03 worldbuilding-authoring）；发散经 SA01（S02） | 核心规则/禁区（带原因）、主要角色心理三角成形 |
| 总纲 | `outline/master-outline.md` | A00（S04 outline-authoring） | `status: 已确认`；结构节点 + 弧光交汇 + 主题落点成形 |
| 卷纲（可选层） | `outline/vol{NN}-outline.md` | A00（S04） | `status: 已确认`；本卷结构节点 + 弧光阶段 |
| 章纲 | `outline/ch{NNN}-outline.md` | A00（S04） | `status: 已确认`；每场景三段式完整 |
| beat（节拍，**可选辅助**） | `manuscript/ch{NNN}.md` 内的 GFM Alert `> [!BEAT] [场景-{N}-节拍-{M}] 一句话提纲`（`[!BEAT]` 固定，场景坐标 agent 必带、作者可省） | 作者自己写 / A00 辅助设计（S05a）/ 不写 | 有则供 writer 参照；**不是写正文的前提** |
| 正文 | `manuscript/ch{NNN}.md`（正文；含 beat 时哨兵在其上） | 正文：SA02（S05b scene-to-prose）；随写随评：A00 编排"编辑"分身（模式A，见 §2 末） | 一轮随写随评修订后整章终审卡 approve |
| 审校/重构 | `process/review-findings.md`、章纲/正文改写 | SA03（S06）；A00 诊断 + SA02 改写（S07） | verdict 交付 / 重构方案确认 |

```
project.md ─闸0→ 设定/角色 ⇄ ─闸1→ 总纲 →[卷纲]─闸2→ 章纲 ─闸3→ 正文 → 随写随评(编辑·好不好·一轮) → 整章终审 → 审校/重构
                （正文前可选先设计 beat：作者写 / A00 辅助 / 无。有 beat 按 beat 参照写，无 beat 直接从章纲场景写并自行分段）
                （可反复、可跳；agent 不自越闸；作者显式越闸 → 一次质量提示；缺口先提议补，不硬写）
```

**这是"默认推进序"，不是强制线性**：作者可在任意阶段回上游修改、跳过某层（如中短篇不启用卷纲）、或显式指定直接进入某阶段（FR-2.5）。流程的**方向性**用于两件事：① 判断"该不该进下一步"（门槛，§2）；② 回答"我写到哪了"（status.md，§5）。

**四级叙事层级的职责边界**（澄清 §1.2，杜绝"跳过章纲"）：

- **总纲/卷纲 = 事件级**：结构节点写"发生什么、章节区间、关联哪条弧光"，是全书/全卷的骨架，**不是场景**。
- **章纲 = 场景级**：把某结构节点落成场景三段式（目标/冲突/结果，结果非顺利达成）。**这是写章节的直接依据，事件级总纲不能替代它。**
- **beat = 场景内节拍（可选辅助）**：场景的下一级展开，每 beat 一句核心点、因果必然，作为正文里的分段提示（可用哨兵行，也可更自由）。**不是写正文的前提**——可有可无，详见 §2 闸4。

即便中短篇总纲"含全书完整结构细节"（04.2），也**不免除章纲这一层**——总纲的细节是事件级的，写某章前该章的**场景级**章纲必须成形并确认。**章纲是写章节的硬前提，且是整条上游链**（设定 → 角色 → 总纲 → 章纲，逐级前提）；beat 不在这条硬前提里。

## 2. 阶段门槛（进入下一阶段的就绪判据）

每个门槛回答同一个问题：**上游成熟到什么程度，本阶段的产出才可能有质量？** 判据是"倾向判断"而非机械清单（与 S01 路由信号同风格）；核心是一条**反向判据**——"若此刻硬做下一步，会得到什么劣质结果"。

### 闸0 立项就绪（→ 构思/设定）
- premise 四要素（主角/目标/阻碍/赌注）成立；主题命题 + 篇幅规划已定（S11 已含）。
- 不足 → 转 S02 先构思收敛，不代作者虚构。

### 闸1 设定/角色就绪（→ 可搭总纲）
**创作逻辑**：总纲是冲突的蓝图，而durable 的冲突从人物本性长出（SS07）。搭总纲前必须已知"谁、想要什么、为什么会撞上"。
- 主角 + 至少一个核心关系/对立方，各有成形**心理三角**（欲望/恐惧/虚假信念），且两者的欲望-恐惧结构能**天然对撞**（不是外部误会）；
- 世界**核心规则 + 关键禁区（带原因）**已定，足以界定"什么可能发生、要付什么代价"；
- 主题命题清晰且是"**不能被干净回答的问题**"（SS09）；
- **反向判据**：若此刻搭总纲，结构节点会不会全是"事件发生了"而没有"人物为此付出/暴露了什么"？会 → 设定太薄，回 S02/S03 补。

### 闸2 总纲就绪（→ 可细化章纲）
**创作逻辑**：章纲是把总纲某结构节点落到场景；落之前，该节点做什么、推进哪条弧光、落地哪个主题必须清楚。
- 要细化的章/段对应的**结构节点存在**且写清"发生什么 + 关联弧光 +（若有）主题落点"；
- 人物弧光在该节点的**阶段清楚**（承接上一阶段末状态）；伏笔操作对得上总纲伏笔总表；
- 总纲相关段落建议 `status: 已确认`（至少稳定，不会边写边大改）；
- **反向判据**：拿着总纲节点能不能拆出"这一章有哪几场戏、每场目标是什么"？拆不出 → 该节点还太粗，先补总纲/卷纲。

### 闸3 章纲就绪（→ 可写章节）
**创作逻辑**：写手只看章纲就该知道每场戏写什么对话、什么转折——这才是"提纲的价值"。
- 该章 `outline/ch{NNN}-outline.md` **存在且 `status: 已确认`**；
- 每场景**三段式完整**：目标（可验证是否达成）/ 冲突 / 结果（非顺利达成）/ POV / 出场人物；该章结构功能明确；
- **反向判据**：拿着章纲还要不要自己现编冲突和结果？要 → 章纲不合格，补 S04 并确认后再写。
- **这是"章纲=写章节前置必需对象"的落点**：一旦作品分章节，写第 N 章前该章章纲必须先成形并确认；不必一次建全部章纲（懒创建的时机灵活性保留），但**绝不从事件级总纲直接写正文**。

### 闸4 beat 是可选辅助（**非门槛**）

**beat 不是写正文的前提**（这是对早期设计的修正——早期把 beat 设为写章节的强制门槛）。真正的正文前提是 **闸3 章纲已确认**；beat 只是章纲与正文之间的一层**可选**脚手架——"一个分段的提醒和构思"。三种来源都合法：**作者自己写 / 让 A00 辅助设计 / 干脆没有**。

- **有 beat** → writer 按 beat 写（与既有逻辑一致，是**参照**而非逐拍填空）；
- **没 beat** → writer 直接从已确认章纲的场景写，自行分段。

**格式 = 扩展 GFM Alert `> [!BEAT] …`，但场景坐标可选**：`[!BEAT]` 是固定标记（提取锚点/可折叠/导出剥离），其后场景坐标 `[场景-{N}-节拍-{M}]` —— **agent 生成必带**（`> [!BEAT] [场景-{N}-节拍-{M}] 一句话提纲`，供一致性核对按场景对齐），**作者手写可省**（`> [!BEAT] 一句话提纲`）。不存在"没有场景坐标就不能写"这回事。beat 若落在正文文件里，导出/归档须剥离（同 §1.2）。

**保真基线**：有 beat 时，一致性核对以正文哨兵 + 已确认章纲为基准；无 beat（或自由格式）时**回落到已确认章纲**为基准。

**开写授权（写作会话）**：写正文仍需一次前置授权（先批意图 → 授权域内块编辑自动累积 → 整章终审），这道授权由 **`confirm_writing_plan` 承载**，但它已**泛化为"写作会话授权（可含 beat）"**——作者要 beat 时 `plan` 装 beat 骨架，不要 beat 时 `plan` 是一句轻量写作意图（"从已确认章纲写第 N 章，范围 X"）；批准同样开会话。授权归属见《04.4》confirm_writing_plan。

**写章节前置状态机**（决定动不动、要不要重确认）：
  1. 章纲不存在或未确认 → **先补章纲（闸3），不写正文**；
  2. **新章、直接写（无 beat）** → `confirm_writing_plan`（轻量写作意图）授权 → 委派 writer 从章纲场景展开、自行分段 → 随写随评一轮 → 整章终审；
  3. **新章、先设计 beat**（作者自己写，或让 A00 辅助）→ A00 辅助时起草 beat → `confirm_writing_plan`（含 beat）→ A00 把 beat 落成正文分段提示 → 委派 writer 展开 → 随写随评 → 终审；
  4. 只改正文（beat 不变，润色/改写）→ 走修订链路（`scene-to-prose`）直接改，不过 `confirm_writing_plan`；（writer 默认能力）
  5. **只改节拍不重写正文** → `confirm_writing_plan` → **A00 改 beat**；正文暂与 beat 不一致是作者显式选择，一致性核对会标记，日后再展开即状态 6；
  6. **节拍 + 正文一起改** → `confirm_writing_plan` → **A00 改 beat** → 委派 writer 重展开受影响区间；
  7. 有正文、**beat 未变、作者无明确要求** → **不重写**，提醒"这章已有内容，要改哪、改 beat 还是局部修订？"（重写保护）。

**两条独立的轴**（不可混）：**轴A beat 层是否变**（A00 增/改/重排/删，beat 变即结构变 ⇒ `confirm_writing_plan`）；**轴B 是否委派 writer（重）展开正文**。

## 2.5 写完之后：编辑评审回路（质量保证的第二道，非门槛）

正文不是"写完即终审"。质量由四道共同守：**输入成熟度**（闸1-3）、**writer 自身技法**（技能只给方向不给细则，见《04.3》§5 技能写作要点）、**编辑评审回路**、**作者终审**。编辑评审有两种模式（"编辑"角色与评审技能的落点见《04.3》§2.5"编辑"）：

- **模式A 随写随评（自动，不入库）**：写完一章草稿后**自动**触发，属"写这一章"的一部分，作者不用另开；**只评"好不好"**（戏剧性 / 人物与声音 / 视角 / 行文 / 结构与节奏 / 主题 / 读者体验），**不做一致性**（单章不跑集成级核查，类比代码写作）。writer 是子 Agent、无 task 工具不能再委派，故由 **A00 在 writer 返稿后编排一个"编辑"分身整体评审** → writer 依判断修订**一轮** → 作者终审。编辑意见**临时、喂这轮修订 + 终审给作者看，不落 `review-findings.md`**（非用户触发不落盘）。
- **模式B 用户触发评审（像 code review，入库存档）**：作者显式要（查一致性 / 整体查 / 全视角查）时，A00 委派编辑（好不好）与一致性核对（对不对，S06/SA03）；全视角 = **好不好一张表 + 一致性一张表**，**都写入 `process/review-findings.md`**（好不好 = 方向建议，一致性 = 可核查缺陷）。**一致性核查只在这条路径跑**（单章随写随评不做）。

**循环边界**：模式A 只自动跑一轮修订就交作者；要再来一轮由作者再喊。不做 writer 内的无人监督长内循环——**作者是最终挑战者**。

## 3. 门槛与作者自主性的和解（软硬原则）

门槛是**质量守门 + 缺口提议**，不是硬锁——否则违背 FR-2.5 与作者权威。

- **Agent 永不自越闸**：进入某阶段前先判断上游就绪度；不足 → 摆出缺口、提议先补，**不静默替作者编上游事实、不硬做**（FR-2.4 / S01 step 9 的"前提缺口回补"从写稿阶段推广到所有跃迁）。
- **作者可显式越闸**（"别管这些，直接写"）→ 照做，但给**一次最小质量风险提示**（"当前章纲未确认，直接写可能需要后续大改"），不重复唠叨；审批红线与安全不因越闸放宽。
- **缺口回补是切换不是挂起**：切上游补齐 → 作者确认 → 回到原任务继续（写作会话保持开启，域外写入照常人工审批，无泄漏面）。
- **门槛判断本身不产生权威状态**：ground truth 是对象文件的 `status` 字段与存在性；门槛只是"读这些 + 判断够不够"，不维护独立的流程状态真相（真相化身见 §5 的非权威约束）。

## 4. 迭代与调整（阶段内/跨阶段的反复）

创作是反复的，流程支持任意回溯，但**调整的传播一律是"提醒"，不是自动连锁**（FR-6.2 / §1.2）：

- **冒泡方向**：改一个 beat = A00 改该哨兵（轴A，过 `confirm_writing_plan`）→ 再**提示**是否让 writer 重写该哨兵统辖的正文区间（轴B，作者可只改节拍不重写=闸4 状态4）；某场景目标/冲突/结果改变 → 提示"是否需要重排该场景全部 beat 哨兵"；章纲改动影响主线 → 提示"是否调整卷纲/总纲"。向上向下的影响都是**提示**，作者决定是否传播。
- **调整颗粒度**：小调整 = 场景 → beat（单章内）；大调整 = 多章场景需要动（可能牵动卷纲/总纲结构节点）。
- **调整后是否/如何重写正文 = 提醒作者，不主动做**（与 §2 闸4 的重写保护一致）。
- **写作时的成批规划**：可一次规划相关几章的章纲（+ 可选 beat）再动笔（`confirm_writing_plan` 支持多章授权）——写某批时该批章纲已完整，避免"边写边现编下游"。

**提交时一致性提醒（细化规则）**：`git_commit` 时若本次提交满足①**回头改了已定稿章节**（触及此前已终审/已 commit 的章，非新写）/ ②**本轮走过 S07 重构** / ③**多章变更**（变更章节数 ≥ 阈值，应用设置项可配，默认约 3）任一，**提醒**作者"建议先做一致性检查再提交"（**提醒非硬锁**，作者可跳，不重复唠叨）。
- **建议的检查范围 = 改动章 + 其影响面**（`find_references` 找被牵连的章），**不是全书**——proportionate；
- **检测手段** = 写作会话/终审记录 + 本次 commit 的 git diff 章节清单比对，**不做全局扫描**（守 §1.4 去数据库化）。

## 5. 流程状态的持久表示：`.iwriter/status.md`

**定位升级**：`.iwriter/status.md` 不再是含糊的"进度提示"，而是**创作流程的状态账本/仪表盘**——记录工程当前在流程中的位置、各阶段门槛通过情况、建议下一步。它是"不用 graph 控流程"时把流程状态外化、可读、可续作的载体。

**非权威 · 可重建（守住 §1.4 去数据库化）**：
- **Ground truth 永远在对象文件**：各 `status` 字段、`manuscript/` 存在性、`confirm_writing_plan`/写作会话登记、`process/open-questions.md`。
- status.md 是这些对象的**派生投影**，可随时从对象重建、会陈旧 → 结论**须与定点读取核对**（沿用 S01 step 8）；
- **更新时机 = 阶段跃迁/门槛通过时机会性更新**（低成本），或作者要求重建时——**绝不做启动全局扫描 / 自动 git diff**（§1.4）；**作者确认后才落盘**（不静默维护）。

**建议 schema**（`.iwriter/status.md`，gitignored）：

| 字段 | 说明 |
| --- | --- |
| 当前阶段 (current-stage) | 流程枚举：立项/设定/总纲/卷纲/章纲/写作/审校/重构 |
