# 小说创作搭子｜AI  Story Buddy：对象模型 详细设计

> 本文档由《03. 小说创作搭子｜AI  Story Buddy：概要设计》§1.3 拆出，是各对象文档字段定义的**权威来源**（SS01-SS05、SS15 schema 参考技能的内容来源）。目录结构与对象映射见 03 §1.1，结构层级与章节命名约定见 03 §1.2，协作记忆/状态摘要/变化叙事的边界见 03 §1.4。**本文中的 §x 章节引用如无特别说明，均指《03. 概要设计》的章节编号。**

* * *

按目录组织，一个对象对应一类工作任务。字段是"必须有"的下限，agent 可视项目情况增补，但缺这些字段视为对象未建立完整。字段命名一律使用 kebab-case；必选字段列前，可选字段列后；示例中字段以标题分节（顶层字段用 H3 级 `###`，嵌套结构按层级递降），便于 agent 用 `get_section` 精确读写单个字段。字段定义本身在运行时以 schema 参考技能的形式存在（SS01-SS05、SS15，见 §2.6），此处是这些技能内容的权威来源。

#### `project.md`（作品对象，单文件，全程仅一份）—— SS01 project-template

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 书名 (title) | 必选 | — |
| 题材/标签 (genre-tags) | 必选 | 自由文本，不限定枚举——题材是作品上下文维度（FR-10），对象层不预设题材分类 |
| 故事核心句 (premise) | 必选 | 必须包含四要素：主角是谁、目标是什么、核心阻碍是什么、赌注（失败代价）是什么 |
| 主题 (theme) | 必选 | 一句话哲学命题，不要求文学化措辞，要求清楚 |
| 读者承诺 (reader-promise) | 必选 | 这本书向读者承诺的核心体验（爽感/悬疑解谜/情感共鸣等），全书不应违背 |
| 篇幅规划 (scale-plan) | 必选 | 预估总字数/章节数量级 + 每章目标字数，决定是否启用卷纲层 |
| 当前版本 (version) | 必选 | 形如 `1.2（初稿补写中）`，语义见 §4 |
| 目标读者 (target-audience) | 可选 | — |

**完整示例：**

```markdown
# project.md

### 书名
照片

### 题材/标签
犯罪、家庭、悬疑

### 故事核心句
退伍老兵阿坤想找回失踪的女儿，但唯一线索指向他曾经背叛过的黑帮，一旦重新接触就可能连累现在的家庭。

### 主题
复仇是否值得付出和解的代价

### 读者承诺
层层剥开的悬疑感 + 父女情感线的揪心

### 篇幅规划
约 25 万字，预计 60 章，每章约 4000 字，启用卷纲层

### 当前版本
0.3（设定收敛中）
```

#### `~/.iwriter/ai/memory/creative/memory.md`（Creative Agent 用户级协作记忆）

`~/.iwriter/ai/memory/creative/memory.md` 是 Creative Agent 与这位作者协作的说明书（用户级、跨项目生效），不是小说状态数据库。它记录"如何与这位作者工作"，不记录"故事现在发生了什么"。它的价值类似 code agent 的用户级长期记忆：帮助 agent 知道作者的偏好、规则与恢复上下文的方法，但真正的事实仍回到工程文件中读取。

路径采用用户级 AI 运行时根（`~/.iwriter/ai/`，见《04.1》§1）下的 `memory/{domain}/memory.md`，而不是 deepagents 默认的 `~/.deepagents/{agentName}/agent.md` 或 `.deepagents/agent.md`：当前 iWriter 已有 edit 与 creative 两个独立 Agent 共用同一套脚手架，记忆是 iWriter 脚手架管理的协作态资产，不应落到 deepagents 默认记忆目录；固定为 `memory/edit/memory.md` 与 `memory/creative/memory.md`，按 domain 隔离，不设共享单一记忆文件，避免 edit 与 creative 把协作规则混成同一个事实来源。**不设项目级协作记忆**——工作区 `.iwriter/` 不存放记忆文件，项目特有的工作流约定由项目级自定义 skills（03 §2.9）或当前对话指令承载。文件名用 `memory.md`，与子 Agent 定义文件 `agent.md`（`subagents/` 根下）区分。

这里必须严格分开两类信息：

- **作品上下文维度**：题材、作品风格、主题、读者承诺、设定约束、已确认风格配置等，属于"要写出什么内容"，应进入 `project.md`、`styles/`、`worldbuilding/`、`characters/`、`outline/` 等正式对象；
- **交互协作维度**：作者成熟度、干预强度、风险偏好、解释深度、澄清频率、默认自主度等，属于"agent 应该怎样和作者协作"，应进入用户级协作记忆 `~/.iwriter/ai/memory/creative/memory.md`，不进入 `project.md`。

参考 code agent：code agent 通常不会在工程配置里设置"用户成熟度/干预强度/风险偏好"这样的业务字段，而是通过系统指令、项目 `AGENTS.md`、长期记忆与当前用户指令落实为行为约束，例如"先读代码再改""不要改生成文件""保持小改动""高风险或意图不清时先问""完成前验证"。`AI Story Buddy` 采用同一类思路：作者成熟度、干预强度、风险偏好不是作品字段，而是用户级协作记忆 `memory.md` 里的协作字段，最终落实为解释颗粒度、澄清阈值、提案数量、影响面预检和审批前说明强度。

适合记录：

- 作者成熟度/协作熟悉度：例如"熟悉长篇结构术语，少解释基础概念"、"需要把专业判断翻译成可操作选择"；
- 干预强度：例如"构思阶段可以多追问和反驳，写稿阶段少打断"、"默认先给 2-3 个方向而不是直接定稿"；
- 风险偏好：例如"跨章节重构必须先列影响面"、"小范围润色不需要长篇说明"；
- 解释与澄清偏好：例如"低风险一句话说明即可"、"高风险先说明依据对象和可能连锁影响"；
- 协作规则：例如"候选方案默认进入 `exploration/`，确认前不得写入正式对象"；
- 上下文恢复策略：例如"事实以工程文件为准；需要状态时按任务读取相关文件；不要因状态摘要过期打断作者"。

建议 `memory.md` 使用人类可读的小节字段，而不是封闭枚举。示例：

```markdown
### 协作偏好
作者熟悉故事结构术语，但不想处理工具细节；低风险修改可以直接给提案，高风险修改先列影响面。

### 干预强度
构思阶段主动提出反例和备选方向；写稿阶段优先保持沉浸，只有前提冲突或越界时打断。

### 风险偏好
跨章节、人物心理三角、核心设定和版本回退必须先确认；局部润色只需简短说明。
```

禁止记录：

- 当前写到第几章、角色当前状态、文件最近变更列表；
- 可从 `project.md`、`worldbuilding/`、`characters/`、`outline/`、`manuscript/` 读取的剧情事实；
- 执行过程中探索到但未被作者确认的临时推断。

更新规则（本期）：`memory.md` **只读装配，agent 不写入**（FR-13.5）；内容由作者手工维护，上面"适合记录/禁止记录"的边界即作者维护时的书写指南，也是后期设计自动更新机制时的边界基础。与用户当前明确指令冲突时，用户当前指令优先；与正式对象文件冲突时，正式对象文件是剧情事实来源，`memory.md` 只作为协作规则参考。记忆的自动沉淀与更新属于整体记忆系统设计，后期统一考虑（FR-13.6）。

结合 deepagents 的落地机制：`createDeepAgent({ memory })` 在 deepagents 1.10.2 中会启用 `createMemoryMiddleware`，该中间件只负责按 `sources` 读取 markdown 记忆并注入系统提示——本期只使用这个读取能力，按 domain 装配 `~/.iwriter/ai/memory/{domain}/memory.md`（不存在时跳过或由 host 以默认模板初始化）。注意 deepagents 默认 memory prompt 会鼓励 agent 在学到偏好时经 `write_file`/`edit_file` 自动更新记忆：装配时必须覆盖该提示为"记忆只读"——记忆文件位于工作区之外，写入会被审批策略层"工作区外自动拒绝"封死，但不覆盖提示会让 agent 反复尝试写入（详见《04.1》§4）。

#### `.iwriter/status.md`（创作流程状态账本，派生/非权威）

定位：记录工程当前在创作流程（设定/角色 → 总纲 →[卷纲]→ 章纲 →（可选 beat）→ 正文 → 审校）中的位置、各阶段门槛通过情况与建议下一步（《04.5》§5）。它是对象文件的**派生投影**，非权威、可重建（见本节末与《04.5》§5）。

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 重建时间 (rebuilt-at) | 必选 | ISO 时间戳，仅表示摘要生成时间，不作为会话启动时自动 diff 的触发依据 |
| 当前阶段 (current-stage) | 可选 | 流程枚举：立项/设定/总纲/卷纲/章纲/写作/审校/重构 |
| 门槛状态 (gates) | 可选 | 闸0-闸4 通过情况：设定就绪? 总纲 status? 卷纲? （判据见《04.5》§2） |
| 已确认章纲 (confirmed-outlines) | 可选 | `status: confirmed` 的 `ch{NNN}-outline.md` 清单 |
| 已写/已终审 (drafted-finalized) | 可选 | 已有正文 / 已过整章终审的章节清单 |
| 建议下一步 (next-step) | 可选 | 基于门槛判断给出的推进建议 |
| 当前进度 (progress) | 可选 | 写到第几章、最近一次写作动作；只能作为快速提示，不能替代读取正式对象 |
| 角色状态摘要 (character-status-digest) | 可选 | 每个重要角色当前所处弧光阶段的一句话摘要，详情指向 `characters/{slug}.md` |
| 开放伏笔摘要 (open-threads-digest) | 可选 | 指向 `outline/master-outline.md` 伏笔总表里尚未回收的条目 |
| 写作约束摘要 (writing-constraints-digest) | 可选 | 视角/时态/基调，从 `worldbuilding.md` 与已确认章纲提炼，不重复定义 |
| 待解决摘要 (open-questions-digest) | 可选 | 指向 `process/open-questions.md` 中状态为"待决策"的条目 |

`status.md` 不是数据源，是**可丢弃、可重建、按需读取的派生摘要缓存**，目标 500-1000 token。系统不在会话启动时为了它主动执行全局 diff、mtime 扫描或全量重建；只有当任务确实需要快速获得全局态势，且逐个读取正式对象成本过高时，agent 才读取它或向作者提议重建。`status.md` 缺失、过期或与正式对象冲突时，不能凭它继续推断，也不应默认打断作者；正确做法是按当前任务读取相关正式对象，必要时再重建摘要。

不存在"作者直接编辑 `status.md` 来改设定"这种用法——作者要改设定，改 `worldbuilding/worldbuilding.md` 本身。使用时机：写作任务开始前、审校全稿扫描前、查证任务需要快速定位当前故事状态时；不需要每次对话都读取，agent 按需加载。

#### `worldbuilding/worldbuilding.md`（设定对象）—— SS02 worldbuilding-schema

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 规则体系 (rule-systems) | 必选 | 题材相关：magic system / 科技水平 / 社会运作规则；现实主义题材可填"无超自然规则，遵循现实社会运作规则"。要求写到"这条规则在什么情况下会被测试/违反会怎样"，不是纯背景介绍 |
| 禁区 (forbidden-zones) | 必选 | 绝对不能出现的设定矛盾，必须写明原因（"因为 X 会破坏 Y 设定的根基"，不是只列"不能做 X"） |
| 时代背景 (era) | 可选 | — |
| 阵营与势力 (factions) | 可选 | 每个阵营的诉求、与主角的关系；规模变大后拆到 `factions.md` |
| 地理信息 (geography-locations) | 可选 | 地理、城镇、地图、场景档案；规模变大后拆到 `geography.md` |
| 历史沿革 (history-timeline) | 可选 | 世界历史、故事时间线、重大历史事件 |
| 关键物品 (key-items) | 可选 | 只登记满足以下之一的物品：**带专属规则/约束**（剑认主，非血脉拔不出）、**需跨章追踪归属或状态**、或**本身是剧情驱动核心**（麦高芬）。普通道具不登记（照 characters-template"路人不升格到独立档案"的门槛）。每条写{意义/功能, 约束规则, 归属流转的追踪要点}。只写**恒定定义**：物品的**当前状态**（此刻在谁手里/在哪/是否损坏）是剧情，其权威来源是 `outline/` 与 `manuscript/` 的当前叙述（与角色档案"不设当前状态字段"同一原则），需要全局快照时读可丢弃的 `.iwriter/status.md` 缓存，不写在此。**与 rule-systems 的分工**：物品**特有**的约束写在本条目；若该物品是某套普适系统的实例（如"这把剑遵循通用魔法体系的法力上限"），系统规则留在 rule-systems，此处只写特有部分并引用系统，不重复。规模变大后拆到 `items.md` |
| 名词体系 (terminology) | 可选 | **长尾专名的标准写法登记处**：招式名、黑话/行话、次要物品名、特殊概念等——需要统一写法、但不够格建独立对象的专名。**有归属对象的专名不在此重复登记**（主角名在 `characters/` 的 name-aliases、主要地名在 geography、阵营名在 factions），避免冗余与漂移。精修期一致性核对时，工具从各归属对象读权威名 + 从本表读长尾 |

规模增长后可拆分为 `worldbuilding.md`（规则/时代/历史）+ `factions.md`（阵营）+ `items.md`（关键物品），拆分时机由 agent 判断（"够用就不拆"原则），不强制预先拆分。

**完整示例：**

```markdown
# worldbuilding/worldbuilding.md

### 规则体系
无超自然规则，遵循现实社会运作规则；黑帮势力的运作逻辑遵循"人情债优先于法律"

### 禁区
阿坤不能轻易诉诸暴力解决问题——因为这会摧毁"他已经改过自新"这条主题落点的根基

### 时代背景
当代，南方某港口城市

### 阵营与势力
→ worldbuilding/factions.md

### 关键物品
- **那本旧账本**：记录了和盛帮二十年的走私流水，是全书的核心筹码（剧情驱动核心）。约束：账本一旦公开，阿坤和老周的攻守关系立刻反转，不能在第三幕前泄露内容。（当前在谁手里 → 以 outline/manuscript 当前叙述为准，不在此登记）

### 名词体系
| 标准写法 | 类型 | 说明 |
| --- | --- | --- |
| 跑单 | 黑话 | 帮内指"临时接一趟走私运输"，勿写作"跑腿" |
| 收线 | 黑话 | 指"结清一笔人情债"，与"收工"区分 |
```

（注：主角名"阿坤/陈国坤"不列此表——它的权威写法在 `characters/阿坤.md` 的 name-aliases；"和盛帮"的权威写法在 factions。本表只收没有归属对象的长尾专名。）

#### `characters/{slug}.md`（重要角色个人档案）—— SS03 characters-template

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 姓名/别名 (name-aliases) | 必选 | — |
| 角色重要性 (importance-tier) | 必选 | 主角 / 重要配角 / 配角——路人不升格到独立档案 |
| 功能定位 (story-function) | 必选 | 自由文本，如"导师"/"对手"/"催化者"——这个角色在叙事机器里承担什么功能，不是性格描述 |
| 外显特征 (visible-traits) | 必选 | 性别、年龄、身体状态、阶层、职业、语域——常识问题（FR-1.2 对应需求 issues#3）的直接解法：移动速度、情绪外露程度、说话方式都应能从这组字段机械推导 |
| 核心欲望 (desire) | 必选 | 心理三角之一 |
| 核心恐惧 (fear) | 必选 | 心理三角之一 |
| 虚假信念 (false-belief) | 必选 | 心理三角之一，要求是"可被推翻的错误认知"而非性格标签——例：「他相信展现脆弱等于失去尊重」是虚假信念，"他很骄傲"不是 |
| 成长弧光 (arc) | 必选 | 初始状态 → 目标状态 → 当前阶段，三段都填 |
| 关系网络 (relationships) | 必选 | 与其他角色的关系，双向标注（A 对 B 的认知 ≠ B 对 A 的认知，这种不对称往往是冲突来源） |
| 声音特征 (voice) | 必选 | 词汇选择/语速节奏/惯常沉默点 |
| 关键能力/资源 (key-abilities) | 可选 | 仅当直接影响情节可行性时才需要填 |
| 独特背景 (background) | 可选 | 只写"会被正文引用到"的过去经历 |

角色档案是**纯安定事实对象**，只登记"不随剧情瞬间改变的、关于角色本身为真的事"。刻意**不设**两类字段，避免手工维护的派生/动态状态混入（去数据库化，§1.4）：**出场章节索引**——由 `find_references(name)` 按需解析（04.4），档案不存索引，杜绝陈腐化；**当前状态**——角色的即时处境是剧情、其权威来源是 `outline/` 与 `manuscript/`，"今处于哪个成长阶段"由本表的 arc「当前阶段」承担，需要全局态势快照时读可丢弃的 `.iwriter/status.md` 缓存。

**完整示例：**

```markdown
# characters/老周.md

### 姓名/别名
老周

### 角色重要性
配角

### 功能定位
信息掮客 / 道义考验

### 外显特征
男，58 岁，码头退休搬运工，左手缺两指（旧工伤），说话直接不绕弯

### 核心欲望
尽快还清对和盛帮的旧债，不再被任何人欠人情

### 核心恐惧
被卷入下一代的麻烦里，连累已经成家的女儿

### 虚假信念
他相信"还清债就能彻底脱身"——事实上和盛帮从不真正放人走

### 成长弧光

### 关系网络

### 声音特征
短句，少修饰，习惯用"行了""算了"收尾对话
```

#### `characters/characters.md`（全部角色登记表，单文件）

角色的**唯一名单入口**：不论一个角色是否已升格为独立档案，都必须在这里有一条记录——已升格的角色只保留一句引用，不复制内容。登记表是表格形态：编辑走 §2.12 的容器级整表替换，不适用逐字段 `get_section`——条目短，整表替换成本可接受。

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 姓名 (name) | 必选 | — |
| 档案状态 (profile-status) | 必选 | 合集内 / 已升格——已升格时本条目只保留引用 |
| 功能定位 (story-function) | 条件必选（合集内） | 信使/路人/反派打手/导师，一词 |
| 与主角关系 (relation-to-protagonist) | 条件必选（合集内） | 一句话 |
| 显著特征 (notable-traits) | 条件必选（合集内） | 1-2 句，够区分声音即可 |
| 独立建档标记 (profile-flag) | 可选 | 待决策 / 已建议 / 已拒绝 |
| 独立档案引用 (profile-ref) | 条件必选（已升格） | 形如 `→ characters/老周.md` |
| 别名 (aliases) | 可选 | 该角色的其他称呼，供 `find_references` 别名解析——合集内角色没有独立档案的 name-aliases 字段，此列补位 |

**完整示例：**

```markdown
# characters/characters.md

| 姓名 | 档案状态 | 功能定位 | 与主角关系 | 显著特征 | 独立建档标记 | 独立档案引用 |
| --- | --- | --- | --- | --- | --- | --- |
| 老周 | 已升格 | | | | | → characters/老周.md |
| 阿坤的妹妹 | 合集内 | 信使 | 唯一还愿意和阿坤说话的家人 | 说话快，爱替阿坤操心 | 已建议 | |
| 货运站柜员 | 合集内 | 路人 | 无 | 只在 ch002 出现一次，没有显著特征 | | |
```

**角色独立建档的阈值规则**：

- **触发独立建档**（满足任一条件即可）：① 该角色在第 2 个不同章节中出现实质性动作/对话（不只是被提及）；② 作者明确指定该角色重要；③ 该角色承担一条独立副线。
- **人数豁免阈值**：当前"重要角色"总量（已独立建档 + 已满足升级条件待处理）**≤ 5** 时允许继续合并；超过 5 后，新触发升级条件的角色强制走一次升格审批（作者可拒绝，拒绝后留在合集里但保留标记，下次再问）。5 是初始可调阈值，写入 `project.md` 或设置项。
- **合集内容溢出信号**：某条目"显著特征"超过 3-4 句时，agent 应主动提议建立独立档案。
- **不做自动降级**：独立档案降级回合集是低频操作，不提供专门工具，按普通文件操作（删除/合并）处理。

#### `outline/master-outline.md`（总纲，单文件，全程仅一份）—— SS04 outline-schema（之一）

> **status 令牌**：三类大纲文件的 status 字段取值为英文令牌 **`draft` / `confirmed`**（新对象一律写英文令牌）。**向后兼容**：早期磁盘对象可能是中文令牌 `草稿中` / `已确认`——生产方（本 schema）与消费方（各就绪门槛/写作会话闸/评审镜头）一律视 `草稿中`≡`draft`、`已确认`≡`confirmed`，读到旧令牌照旧识别、不报未就绪。（对应运行时全英文原则；本节及后文示例已改用英文令牌。）

**未启用卷纲层时**（中短篇），总纲包含全书完整结构细节：

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 状态 (status) | 必选 | draft / confirmed——对应 FR-2.3"候选 vs 已确认前提"，三类大纲文件同此字段 |
| 故事核心句 (premise) | 必选 | 与 `project.md` 一致，此处可展开为 2-3 句 |
| 主题落点 (theme-beats) | 必选 | 主题如何具体化为情节事件——通过哪几个具体情节让读者感受到主题，每个落点指向大致结构节点 |
| 结构节点 (structure-nodes) | 必选 | 默认 8 个题材中立占位节点：开篇钩子 / 激励事件 / 早期试炼 / 中点转折 / 危机加深 / 至暗时刻 / 高潮 / 结局余波。每节点填：发生什么（具体事件）、大致章节区间、关联到哪条人物弧光 |
| 人物弧光交汇点 (arc-intersections) | 必选 | 列出主要角色的弧光在哪些结构节点彼此交汇/冲突 |
| 伏笔总表 (foreshadow-table) | 必选 | 表格：伏笔内容 / 埋设章节 / 回收章节 / 所属结构节点 / 状态（待埋设/已埋设/已回收） |
| 候选方向记录 (candidate-directions) | 可选 | 若主线仍有未收敛的方向，标注"候选"并指向 `exploration/` 对应文件 |

**启用卷纲层时**，总纲只保留全书维度的宏观弧线：

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 状态 (status) | 必选 | 同上 |
| 故事核心句 (premise) | 必选 | 同上 |
| 主题落点 (theme-beats) | 必选 | 全书维度的主题落点 |
| 全书结构弧 (global-arc) | 必选 | 一段话描述全书从开篇到结局的宏观走向，不精确到章节区间 |
| 人物弧光总览 (arc-overview) | 必选 | 每个主要角色的完整弧光（从起点到终点），不细化到卷内阶段 |
| 伏笔总表 (foreshadow-table) | 必选 | 全书维度的伏笔总表，各卷伏笔操作在 vol-outline 内另行记录 |
| 卷纲索引 (volume-index) | 必选 | 列出各卷目标并指向 `vol{NN}-outline.md` |

#### `outline/vol{NN}-outline.md`（卷纲，可选层）—— SS04 outline-schema（之二）

每一卷是全书叙事弧线上的一个独立阶段——有完整的冲突弧线，但故事本身尚未结束。卷纲相当于该卷的详细小总纲：

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 状态 (status) | 必选 | draft / confirmed——同总纲/章纲 |
| 本卷结构功能 (structural-role) | 必选 | 对应 `master-outline.md` 的哪段全书弧线 |
| 本卷结构节点 (structure-nodes) | 必选 | 本卷内部结构节点序列，格式同总纲 |
| 本卷核心冲突 (core-conflict) | 必选 | 本卷阶段性的主要阻碍/反派/危机 |
| 本卷人物弧光阶段 (arc-stage) | 必选 | 各主要角色在本卷经历的弧光阶段，衔接上一卷末状态 |
| 本卷伏笔操作 (foreshadow-ops) | 必选 | 埋设 / 强化 / 回收，与总纲伏笔总表对应 |
| 本卷高潮与收尾 (volume-climax) | 必选 | 本卷内部高潮 + 收尾状态 |
| 章节列表 (chapter-list) | 必选 | 本卷覆盖的章节文件名列表，按故事顺序 |
| 衔接 (transition-notes) | 可选 | 与上一卷承接点、给下一卷的铺垫 |

#### `outline/ch{NNN}-outline.md`（章纲，提纲价值的关键载体；写该章前置必需）—— SS04 outline-schema（之三）

**必需性**：一旦作品分章节，写第 N 章前该章章纲必须先成形并 `status: confirmed`——事件级总纲不能替代场景级章纲，绝不从总纲直接写正文（闸3，《04.5》§2）。懒创建的时机灵活性保留（不必一次建全部章纲），但"写某章"这个动作的前置就是"该章章纲已确认"。

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 本章结构功能 (structural-role) | 必选 | 对应总纲/卷纲的哪个结构节点 |
| 状态 (status) | 必选 | draft / confirmed——对应需求 FR-2.3"候选 vs 已确认前提" |
| 场景列表 (scenes) | 必选 | 核心字段，见下表，一章通常 1-3 个场景 |
| 本章伏笔操作 (foreshadow-ops) | 可选 | 埋设 / 强化 / 回收，逐条对应总纲伏笔总表条目 |
| 开篇钩子/结尾悬念 (hook-cliffhanger) | 可选 | 章节首尾的吸引力设计 |
| 衔接 (transition-notes) | 可选 | 与上一章衔接点、给下一章的过渡铺垫 |

**场景列表字段（每个场景一段，标题格式 `### 场景-{N}`）：**

| 子字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 地点/时间 (location-time) | 必选 | — |
| 出场人物（含 POV）(characters-pov) | 必选 | 若全书用多视角叙事，必须标明本场景的 POV 角色 |
| 目标 (goal) | 必选 | POV 角色这一刻具体想要什么，要求可验证是否达成 |
| 冲突 (conflict) | 必选 | 谁/什么阻止了目标 |
| 结果 (outcome) | 必选 | 达成但代价更大 / 未达成 / 达成但揭示新问题——不能是顺利达成 |
| 情绪基调/节奏 (tone-pacing) | 可选 | 快/慢、紧张/舒缓 |
| 信息释放 (information-reveal) | 可选 | 本场景向读者揭示什么新信息、对谁仍隐藏什么 |

**场景没有独立 status 字段**：状态以章纲**文件**为单位（上表的 status），"已确认章纲的场景"指该章纲文件 status 为 confirmed——S05 等技能表述中的"场景已确认"一律按此语义理解，不存在场景级状态。

**完整示例：**

```markdown
# outline/ch003-outline.md

### 本章结构功能
激励事件的后半段

### 状态
confirmed

### 场景-1

#### 地点/时间
码头仓库，深夜

#### 出场人物
阿坤（POV）、老周

#### 目标
阿坤想让老周说出照片的来源

#### 冲突
老周欠阿坤的人情已经还清，不愿意再卷入

#### 结果
老周说出来源，但代价是要阿坤帮他做一件违法的事——交换条件让阿坤的处境更复杂

#### 情绪基调
压抑，对话为主，节奏慢但张力累积

#### 信息释放
揭示照片来源指向阿坤曾背叛过的黑帮；对读者隐藏老周自己也欠那个黑帮的债
```

这样的章纲才有"提纲的价值"——拿到这份提纲可以直接知道该写什么对话、什么转折，而不是面对一句"阿坤去找老周问线索"自己现编冲突和结果。

#### `manuscript/ch{NNN}.md`（正文，每章一份）

**beat 的表示 = 扩展 GFM Alert `> [!BEAT] …`**（可选辅助、不是写正文的前提——前提是章纲已确认，见《04.5》闸4）。`[!BEAT]` 是 beat 的固定标记（提取锚点），场景坐标是其后可选的对齐信息：

- **生成规则（agent 生成时）**：`> [!BEAT] [场景-{N}-节拍-{M}] 一句话提纲`——`[!BEAT]` 标记 + 场景坐标 `[场景-{N}-节拍-{M}]`（回指章纲场景）**agent 必须带**，供一致性核对按场景对齐；
- **作者手写**：`> [!BEAT] 一句话提纲` 即可，**场景坐标可省**（用户不必编码）；
- **提取规则**：以 `> [!BEAT]` 这个 alert 标记识别 beat 行（不靠 `[场景-…]` 正则匹配）；坐标存在则解析用于场景对齐，缺失则该 beat 回落到"以章纲场景为基准"；
- **统辖区间定界**：从某 `[!BEAT]` 行之后到下一个 `[!BEAT]` 行（不含）或文件末尾；场景区间 = 其全部 beat 区间之并，场景切换点 = 坐标场景序号变化处（坐标缺失的 beat 不参与场景切分，归属当前场景）；
- **脚手架非作品内容**：`[!BEAT]` 标记稳定可识别，**定稿归档与任何导出产物必须剥离**（剥离规则属格式转换层）；编辑器中作为 alert 可折叠/弱化渲染，作者可见、可直接改提纲本身。

**无 beat 是合法状态**——writer 直接从章纲场景写、自行分段。文件名与 `outline/ch{NNN}-outline.md` 遵循相同的三级命名约定。

#### `process/open-questions.md`（过程对象，单文件）

登记**创作决策层面**悬而未决的问题——故事该怎么走、设定有没有矛盾——不是开发缺陷或技术 TODO。**与 `process/review-findings.md` 的边界**：open-questions 登记"作者要做的选择"（决策问题），review-findings 登记"稿件要修的错"（执行性缺陷）；审校中发现需要作者裁决故事走向的问题登记到本文件，正文缺陷进 review-findings。

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 问题描述 (question) | 必选 | — |
| 出现章节/上下文 (context-ref) | 必选 | — |
| 提出时间 (raised-at) | 必选 | — |
| 状态 (status) | 必选 | 待决策 / 已解决 |
| 解决后归档去向 (resolved-into) | 条件必选（已解决） | 若解决方式是写入某个对象文件，记录指向哪个文件 |

**完整示例：**

```markdown
# process/open-questions.md

## 女儿失踪当年的真相要不要在卷一揭示？

### 出现章节/上下文
ch003，老周交出线索后

### 提出时间
2026-03-01

### 状态
待决策
```

#### `process/changelog.md`（过程对象，单文件）

承担**累积性创作叙事**：作者/agent 用人类语言记录"这次为什么这么改、对故事产生了什么影响"——这是 git commit message 不会写、`.iwriter/status.md`（无历史的即时快照）也不承担的东西。单文件追加写，按时间顺序堆叠。它只记录已确认的重要变化，不是每次工具调用或每次写作动作的自动流水账。

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 时间/版本号 (timestamp-version) | 必选 | 记录时间，若恰逢版本号变化可一并记录 tag |
| 变更摘要 (summary) | 必选 | — |
| 影响范围 (scope) | 必选 | 涉及哪些对象文件/章节 |
| 触发原因 (trigger) | 必选 | 大修 / 精修 / 问题修补 / 版本回退 |

**完整示例：**

```markdown
# process/changelog.md

## 2026-03-10（0.3 → 0.4）

### 变更摘要
把老周的核心恐惧从"怕死"改成"怕连累女儿"，原设定和他后续的让步动机冲突

### 影响范围
```

#### `process/review-findings.md`（过程对象，单文件，多条目，可选懒创建）

审校结果与外部反馈问题清单的**持久化落点**（FR-5.4"供后续修订使用"的跨会话载体）。**只有用户触发的评审（模式B）落这里**：作者显式查一致性/整体/全视角时，编辑"好不好"（方向建议）与一致性核对"对不对"（可核查缺陷）各成一张表写入本文件；**模式A 随写随评的编辑意见不落盘**（非用户触发，临时喂修订+终审）。reviewer 对 workspace 只读、发现落 `/large_tool_results/` 检查文件并回传路径+简报；本文件由 **A00 落盘**（读 reviewer 检查文件→写 `review-findings.md`，经普通编辑审批）。外部反馈整理默认提议落盘。修订任务（S05 修订链路）以本文件为输入，修复后顺带更新条目状态（经审批）。

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 问题描述 (finding) | 必选 | — |
| 等级 (severity) | 必选 | 高 / 中 / 低——沿用 S06 固定交付格式的分级 |
| 依据对象/位置 (evidence-refs) | 必选 | 判断依据的对象与问题所在章节/场景（映射到具体对象，FR-5.4） |
| 来源 (source) | 必选 | agent 自查（附核查颗粒度/批次）/ 外部反馈（试读意见） |
| 建议 (suggestion) | 必选 | 可执行的处理建议 |
| 记录时间 (recorded-at) | 必选 | — |
| 状态 (status) | 必选 | 待处理 / 已修复 / 已忽略（作者裁决不改） |
| 处理去向 (resolved-into) | 条件必选（已修复） | 指向修订所落的章节/对象 |

#### `materials/fragments.md`（素材对象，单文件，多条目）

素材捕获区 + 路由前的暂存区，涵盖"一句对话、一个场景念头、一个人物细节、一个伏笔想法"这类归宿不同的碎片。

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 原始内容 (raw-content) | 必选 | 一句话/几个词/情绪/问题，**不强制作者分类**——零摩擦记录是核心价值 |
| 采用状态 (adoption-status) | 必选 | 未采用 / 已采用 |
| 类型 (type) | 必选 | 场景念头 / 对话片段 / 人物细节 / 伏笔想法 / 情绪意象 / 调研笔记 / 未分类——**agent 在处理相关任务时顺带标注**，作为编辑动作提交审批 |
| 记录时间 (recorded-at) | 必选 | 用于按时序排序素材 |
| 关联线索 (related-refs) | 可选 | 可能关联的角色/章节/结构节点，agent 识别后填 |
| 采用去向 (adopted-into) | 条件必选（已采用） | 记录被并入了哪个对象文件 |

#### `styles/{slug}.md`（风格配置对象，可选、懒创建）—— SS05 style-schema

风格提取的产物本质上更接近"项目专属技能"而不是故事事实（不像角色/设定是关于故事世界的事实，它是一套操作化的生成技术），所以单独放 `styles/` 目录，不塞进 `worldbuilding/` 或 `characters/`。

**范文（exemplar）是主锚字段**（03 §7 质量原则）：一段作者拥有的、具体的目标嗓子正文，是 writer 的一等输入——"照这个嗓子写、别抄内容"。其余分析字段（声音/措辞/句法/意象/配方/自检）是**围绕范文的操作化支撑**，帮助解释"这段范文为什么是这个嗓子"，但**当分析字段与范文本身冲突时，以范文为准**；一段好范文胜过十条分析规则。

| 字段（英文名） | 必选/可选 | 说明 |
| --- | --- | --- |
| 风格标识 (slug) | 必选 | — |
| 来源说明 (source-author) | 必选 | 一句话说明提炼自谁的范文，不是凭空定义 |
| **范文 (exemplar)** | **必选（主锚）** | **一段具体的目标嗓子正文（作者拥有/提供），writer 照其嗓子写、不抄内容；outrank 下列分析字段与通用 craft** |
| 声音 (voice) | 可选（支撑） | 围绕范文的操作化说明：叙述者姿态/距离/情感温度 |
| 措辞 (diction) | 可选（支撑） | 词汇偏好、禁用词 |
| 句法 (syntax) | 可选（支撑） | 句长模式、标志性句式、标点 |
| 意象 (imagery) | 可选（支撑） | 反复出现的意象、感官通道 |
| 生成配方 (generation-recipe) | 可选（支撑） | 写稿时可参照的操作化步骤，不是文学评论；不得写成逐句可数规则（issues#4） |
| 自检清单 (self-check) | 可选（支撑） | 审校时核对的检查点 |
| 采用范围 (scope) | 必选 | 全书默认应用 / 仅特定人物对话适用 等 |

**完整示例：**

```markdown
# styles/lu-xun.md

### 风格标识
lu-xun

### 来源说明
提炼自作者提供的《孔乙己》《故乡》节选

### 范文
（主锚——照这个嗓子写、别抄内容）
> 我到现在终于没有见——大约孔乙己的确死了。……他从破衣袋里摸出四文大钱，放在我手里，见他满手是泥，原来他便用这手走来的。

### 声音
冷静克制的旁观者，情感藏在白描之下，偶尔以反讽刺破表面平静

### 措辞
偏好具体名词而非抽象形容词；不用"仿佛""似乎"这类模糊化措辞

### 句法
短句为主，长短句交替制造停顿；对话极简，很少用修饰性副词

### 生成配方
1. 先写动作/场景的白描，不直接写情绪
2. 情绪通过一个具体细节侧面带出，不直接命名情绪词
3. 对话保留口语化断句，不补全书面语法

### 自检清单
- 是否出现了"仿佛""似乎"等被禁止的模糊化措辞？
- 情绪是否被直接命名（如"他很难过"），而不是通过细节呈现？

### 采用范围
全书默认应用
```
