## 过程中被反复纠正的工作方式（继续这项工作要延续，不要回退）

- **不默认保留现有实现的任何设计/工具/Agent**——每一项都要单独论证是否复用得上，复用不是默认项。用户多次明确反对"图简单或考虑兼容、过多采用原来的设计"。
- **判断必须用代码事实核实，不能凭印象或旧文档断言**。这次过程中至少两次因为没核实代码而出错，被用户当场纠正：
  - 误判 `electron/ai/skills/creative/` 目录不存在 → 实际 skills 在 `electron/ai/builtin-skills/creative/` 下，已有 29 个真实 `SKILL.md` 文件。
  - 把已经在更早代码演进中废弃的 `run_consistency_check` 工具当作"该保留"重新写回设计——当前系统提示词里明文写着"Do NOT call run_consistency_check. Use consistency_checker subagent only."。
- **用户倾向于持续做减法**，会反复追问"这个真的有必要吗""DocumentTools 能不能直接做"。这个追问每次追下去基本都对——creative 专用工具最终从最初设想的 18+ 个收缩到 2 个（`find_references` + `confirm_writing_plan`）。下次再有"要不要加一个专用工具/专用 Agent"的设计冲动时，先按 §5.1 的两条判据自己过一遍，而不是假设"这次不一样"。
- **文档正文不要假设旧版本仍可查阅**。之前犯过一次具体错误：在 §1.4 写"其余对象字段定义与 vN 完全相同"，但 vN 文件已经被覆盖、根本不存在，导致文档实际内容缺失。现在改为：每次修订都让文档自身保持完整自洽，差异交给 git diff，不在正文里互相指代。

## 已确定、不需要重新打开讨论的核心结论（详见设计文档对应章节）

- 对象模型：`project.md`（身份信息）/ `status.md`（原 storybible.md，降级为派生摘要）/ `setting/` / `characters/`（重要角色一人一档 + `_minor-cast.md` 次要角色合集）/ `outline/`（`masterplan.md` 总纲 + 可选 `vol{N}.md` 卷纲 + `ch{NN}-outline.md` 章纲）/ `draft/` / `process/` / `exploration/`（候选区，纯目录约定）。§1
- 章纲核心字段是**场景列表**（目标-冲突-结果三段式），不是一句话核心情节；beat 哨兵挂在场景之下。§1.2~1.4
- Agent 花名册：Researcher / Explorer（已吸纳原 Advisor） / ConsistencyChecker / Writer / WritingStyleExtractor+WritingStyleSkillCreator，**取消 Planner**；全部经 deepagents 原生 `task` 调用，不单独包工具。§3
- 工具最小化：creative 专用工具只剩 `find_references` 和 `confirm_writing_plan`；章节管理改为通用文件工具 + `masterplan.md` 的"章节顺序"字段；不再需要 `.iwriter/creative.db`（SQLite），改用极简 `.iwriter/session.json`。§5
- 不做 wiki 式目录/链接语法，但用隐形的 agent 侧 `find_references` 拿到精确反向引用的价值。§1.7
- 反向导入已有小说是独立的首次导入场景，不是迁移的边角情况；提炼内容都是候选，需作者确认。§8.2
- 角色文件粒度规则有具体阈值（5 人豁免、`_minor-cast.md` 条目超 3-4 句提议升级）。§1.5
