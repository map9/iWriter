## 阅读须知（StoryForge 与 agent 架构的根本差异）

StoryForge **不是 agent 架构**，没有"总 agent 编排 + 子 agent 执行"。它的每一次 LLM 调用都是 **UI 按钮 → 固定 adapter → 一次 `chat/completions`**：编排与调度由 App 的界面交互和固化流程完成，AI 只做某个固定 worker 的活。因此下面每个 `# llm call` = **一个 moduleKey / adapter = 一个独立的、无状态的单发调用**，各自有自己的 system prompt 和上下文装配，彼此不共享会话。

每次调用的通用装配机制：

- **prompt** = `renderPrompt(模板, ctx, {parameterValues, overrides})`。模板是内置 `PromptSeed`（用户可克隆改写）；`{{var}}` 变量替换、`{{#if}}` 条件块、可调参数、few-shot 好/坏示例自动拼接。下面给出的是**内置默认 system prompt + userPromptTemplate 原文**。
- **context** = 模板里的 `{{变量}}` 槽位，由两条路径填充：① 结构化上下文源 `assembleContext({sourceKeys})`（34 个 `CONTEXT_SOURCES`，分层预算裁剪，`L0` 不裁）；② `context-builder.ts` 的格式化函数（`buildWorldContext` / `buildCharacterContext` / `buildCreativeRulesContext` …）。下面每个调用的「context」列出实际填入的槽位与来源。

# llm call · 灵感反推

## 概要
- **name**: `inspiration.reverse`（多世界版 `inspiration.reverse.multiworld`）
- **role**: 资深小说策划师 —— 从碎片灵感反向推演完整故事框架
- **工作内容**: 用户写一段模糊想法/关键词/片段，AI 一次性反推出「世界观概要 + 故事核心 + 2-5 个初始角色卡」的结构化草稿，供用户二次编辑后采纳写回 `worldviews` / `storyCores` / `characters`。

## prompt

````text
[system]
你是一位资深的小说策划师，擅长从碎片灵感中提炼出完整的故事框架。

═══ 任务 ═══
用户提供了一段碎片灵感（可能只是模糊的想法、几个关键词、一个场景片段、甚至一句话）。
你需要从这段灵感出发，**反向推演**出完整的故事框架：

1. **世界观概要**：故事发生的世界是什么样的？包括背景、地理、社会结构等核心要素
2. **故事核心**：主题是什么？核心冲突是什么？情节模式是什么？一句话概括故事
3. **初始角色**：2-5 个关键角色，包括主角、核心配角、主要对手

═══ 设计原则 ═══
- 忠实于用户灵感的核心意象和情感方向，不要偏离用户表达的核心想法
- 世界观为故事服务——不需要大而全，只需要支撑故事核心冲突
- 角色设计要有鲜明反差和冲突潜力
- 所有内容都是草稿，用户会二次编辑，所以大胆发挥但保持逻辑自洽
- 角色数量控制在 2-5 个，宁少勿多

═══ 输出格式 ═══
输出一个 JSON 对象，严格按以下结构：

```json
{
  "worldview": {
    "worldOrigin": "世界来源/创世背景（100-200字…）",
    "powerHierarchy": "力量体系（如何分层、怎么晋升）",
    "continentLayout": "大陆/地貌分布概述",
    "climateByRegion": "气候与环境特征",
    "historyLine": "世界历史线概述",
    "races": "种族/民族设定",
    "factionLayout": "势力分布"
  },
  "storyCore": {
    "logline": "一句话故事（20-40字）",
    "theme": "核心主题",
    "centralConflict": "核心冲突",
    "plotPattern": "情节模式（成长型/复仇型/探索型/争霸型等）",
    "mainPlot": "故事主线概述（50-100字）"
  },
  "characters": [
    { "name": "", "roleWeight": "main/secondary/npc/extra",
      "moralAxis": "good/neutral/evil", "orderAxis": "lawful/neutral/chaotic",
      "shortDescription": "", "personality": "", "background": "",
      "motivation": "", "arc": "" }
  ]
}
```
注意：每个字段都要有实质内容；角色必须填 roleWeight/moralAxis/orderAxis；一句话故事要精炼抓人。

[user]
{{#if projectName}}【作品名】{{projectName}}{{/if}}
{{#if genres}}【倾向题材】{{genres}}{{/if}}

═══ 我的灵感 ═══
{{inspiration}}

{{#if userHint}}【补充说明】{{userHint}}{{/if}}

请从这段灵感出发，反向推演出完整的故事框架（世界观 + 故事核心 + 角色）。
````

## context
上下文极薄：只有用户灵感 + 项目名/题材，**不读任何已有设定**（它是链条的起点，负责"从无到有"）。

### 各个部分内容详细说明
- `inspiration`：用户在灵感面板输入的自由文本（本调用的唯一实质输入）。
- `projectName` / `genres`：项目概况里的名称与题材标签。
- `userHint`：可选补充说明。
- 多世界版 `inspiration.reverse.multiworld` 额外让模型产出多个 `world` 对象（含 `entryCondition` / `powerRestriction`）与角色的 `homeWorld` / `isCrossWorld`。

# llm call · 故事核心生成

## 概要
- **name**: `story.generate`
- **role**: 资深故事架构师 —— 在世界观基础上构思故事核心
- **工作内容**: 为故事核心的**单个维度**（一句话/概念/主题/核心冲突/情节模式/主线/复线）生成内容，采纳写回 `storyCores` 对应字段。

## prompt

````text
[system]
你是一位资深的故事架构师，擅长在世界观基础上构思引人入胜的故事核心{{#if usesTone}}（基调：{{tone}}）{{/if}}。

设计原则：
1. 故事核心要有明确的主题与情感张力
2. 核心冲突要有层次（外在冲突 + 内在冲突）
3. 与世界观底层逻辑自洽
4. 避免落入俗套，但保留爽点和共鸣

输出要求：直接输出内容，使用 Markdown，简明扼要{{#if usesDetailLevel}}（详尽度：{{detailLevel}}）{{/if}}。

[user]
小说名称：{{projectName}}
小说类型：{{genres}}
需要生成的故事维度：{{dimension}}{{#if worldContext}}

世界观摘要（保持自洽）：
{{worldContext}}{{/if}}{{#if userHint}}

用户补充说明：{{userHint}}{{/if}}
````
可调参数：`tone`（严肃/热血/抒情/黑暗/温情/宿命）、`detailLevel`（一句话/简略/中等/详尽）。

## context
项目名/题材 + 目标维度 + 世界观摘要。

### 各个部分内容详细说明
- `dimension`：要生成的故事核心字段（logline / theme / centralConflict / plotPattern / mainPlot / subPlots）。
- `worldContext`：由 `formatWorldviewBlock()` 从当前 `worldviews` 记录格式化的【世界观】块（多字段：世界来源/力量体系/地貌/历史/种族/势力…），保证故事核心与世界观自洽。
- `projectName` / `genres` / `userHint`：项目元信息与可选补充。

# llm call · 世界观维度生成

## 概要
- **name**: `worldview.dimension`（另有 `worldview.divine` / `worldview.divine.split` 处理神明设定）
- **role**: 资深世界设计师 —— 构建宏大自洽有深度的虚构世界
- **工作内容**: 为世界观的**单个维度**（地理/历史/社会/文化/经济/规则/自然/人文/摘要）生成内容，写回 `worldviews` 对应字段。system prompt 内置了整段**历史地理学人地互动常识**作为方法论强约束。

## prompt

````text
[system]
你是一位资深的世界设计师，擅长构建宏大、自洽、有深度的虚构世界{{#if usesTone}}，写作基调偏{{tone}}{{/if}}。

你的职责：
1. 根据用户提供的小说类型和基本设定，为其构建详细的世界观要素
2. 确保世界观各维度之间逻辑自洽
3. 提供具体、生动的细节，而非泛泛而谈
4. 用条理清晰的格式组织内容

**【历史地理学 · 人地互动常识】**（构建自然 / 人文环境时务必遵循，除非「世界规则」明确要求架空突破）：
- **环境定生计**：平原河谷宜农耕…草原荒漠多游牧…沿海沿湖多渔商…生计形态由水土气候决定。
- **聚落择水而居**：人口与城镇密集于大河流域、湖畔、河口、海岸、绿洲、泉源…文明多发源于大河两岸。
- **城因利而聚**：城市多生于交通节点、资源地、险要防地与行政/宗教中心。
- **城有等级腹地**：聚落分大都—州城—市镇—乡村多级…人口随土地承载力分布，绝不均匀。
- **水运胜陆运**：河海运输远比陆运廉价…距离越远联系越弱（距离衰减）。
- **山河定疆界**：大山脉、宽江、沙海、海峡常成势力/国家/文化的天然边界。
- **隔绝生分异**：地理隔绝催生方言、独立族群与异质文化。
- **沧海桑田**：河流改道、海岸进退、气候冷暖、沙漠化令城市与文明兴衰…
- 综上让「地理→资源→生计→人口→城池→交通→势力→兴衰」成自洽链条，杜绝"沙漠中心建超级都市"等反常识设定。{{#if worldRulesContext}}

**【重要】世界规则约束**：本作品设定了「真实与幻想」规则。标注为「📜取自真实」的内容必须准确、不得时代错乱；「✨架空改造」尊重作者设定；冲突时按各维度优先级裁决。发现前提与史实锚点矛盾必须在回答开头指出并给替代方案。{{/if}}

输出要求：
- 直接输出内容，不需要重复用户的输入
- 使用 Markdown 格式
- 内容要丰富具体，有画面感
- 注意与已有世界观设定保持一致{{#if usesDetailLevel}}
- 详尽度：{{detailLevel}}（简略=300字内 / 中等=300-800字 / 详尽=800-1500字）{{/if}}

[user]
小说名称：{{projectName}}
小说类型：{{genres}}
需要生成的维度：{{dimension}}{{#if worldContext}}

已有世界观设定（请保持一致）：
{{worldContext}}{{/if}}{{#if worldRulesContext}}

{{worldRulesContext}}{{/if}}{{#if userHint}}

用户补充说明：{{userHint}}{{/if}}{{#if isSummary}}

请将上述世界观浓缩为 200-400 字的精华摘要，后续 AI 写作时会作为核心上下文参考。{{/if}}
````
可调参数：`tone`（严肃/史诗/抒情/硬核/轻奇幻）、`detailLevel`。

## context
目标维度 + 已有世界观（保持一致）+ 真实与幻想规则。

### 各个部分内容详细说明
- `dimension`：要生成的世界观字段（worldOrigin / powerHierarchy / continentLayout / climateByRegion / races / factionLayout / …）。
- `worldContext`：`formatWorldviewBlock()` 输出的已有世界观全字段块，让新维度与既有维度自洽。
- `worldRulesContext`：来自 `worldRules` 上下文源（真实与幻想清单，含 📜取自真实 / ✨架空 标注 + 优先级），触发 system 里的世界规则约束段。
- `isSummary`：当生成"摘要"维度时置真，切换为"浓缩 200-400 字"模式（该摘要即后续几乎所有调用的 `worldContext` 主来源）。

# llm call · 创作规则生成

## 概要
- **name**: `rules.generate`
- **role**: 资深创作顾问 —— 明确创作规则与风格约束
- **工作内容**: 针对指定规则维度（写作风格/叙事视角/基调氛围/禁忌等）给出"该做什么 + 不该做什么"的可执行建议，写回 `creativeRules`。

## prompt

````text
[system]
你是一位资深的创作顾问，擅长帮作者明确创作规则与风格约束，避免后续行文偏移{{#if usesStrictness}}（约束力度：{{strictness}}）{{/if}}。

输出要求：
- 针对用户指定的规则维度（写作风格/叙事视角/基调氛围/禁忌等），给出具体可执行的建议
- 不要泛泛而谈，每条都要有「该做什么」+「不该做什么」
- 用 Markdown 列表

[user]
小说：{{projectName}}（{{genres}}）
需要生成的规则维度：{{dimension}}{{#if worldContext}}

世界观摘要：
{{worldContext}}{{/if}}{{#if storyCore}}

故事核心：
{{storyCore}}{{/if}}{{#if userHint}}

用户补充：{{userHint}}{{/if}}
````
可调参数：`strictness`（宽松/中等/严格）。

## context
维度 + 世界观摘要 + 故事核心。

### 各个部分内容详细说明
- `dimension`：writingStyle / narrativePOV / atmosphere / prohibitions / consistencyRules / specialRequirements。
- `worldContext` / `storyCore`：世界观摘要块与 `formatStoryCoreBlock()` 输出，使规则贴合作品。
- 说明：创作规则采纳后，会经 `buildCreativeRulesContext()` 反过来进入下游正文/大纲生成的 prompt（写作风格/视角/基调/禁忌/一致性规则）。

# llm call · 多世界建议 / 扩展

## 概要
- **name**: `world-group.suggest` / `world-group.expand`（adapter `world-group-ai.ts`）
- **role**: 多世界架构师
- **工作内容**: `suggest` 基于项目基调建议一组世界（世界组、主世界、跨世界关系）；`expand` 把某个世界组展开为完整世界观。写回 `worldGroups` / `worldviews`。属多世界项目专用，非默认链路。

## prompt

````text
[system]（suggest 要点，随实现内联构造）
你是多世界小说的架构设计师。基于项目题材/故事核心，建议 N 个相互关联的世界组，
每个含：世界名、类型、一句话定位、与主世界的关系（并列/嵌套/平行/因果）。
输出严格 JSON 数组：[{ "name","type","summary","relationToMain" }]。

[user]
项目：{{projectName}}（{{genres}}）
故事核心：{{storyCore}}
请建议世界组结构。
````

## context
项目名/题材 + 故事核心 + 已有世界组。

### 各个部分内容详细说明
- 读 `world-group-context.ts` 装配的多世界总览（现有世界组、关系、主世界标记）。
- `expand` 额外带被展开世界组的现有字段，产出对齐 `worldviews` v3 字段的完整世界观。

# llm call · 伏笔建议

## 概要
- **name**: `foreshadow.generate`
- **role**: 小说伏笔设计大师
- **工作内容**: 基于世界观/角色/已有伏笔，建议 3-5 个新伏笔（名称/类型/埋设/呼应/回收时机），写回 `foreshadows` 集合。

## prompt

````text
[system]
你是一位精通叙事技巧的小说伏笔设计大师，擅长设计精妙的伏笔和悬念。

你的职责：
1. 根据小说世界观、角色和已有伏笔，建议新的伏笔设计
2. 每个伏笔要包含：名称、类型、埋设方式、呼应建议、回收时机
3. 确保伏笔之间互不冲突，与世界观和角色设定一致
4. 注重伏笔的层次感：有明线伏笔也有暗线伏笔{{#if usesDensity}}
5. 本次设计的伏笔密度偏：{{density}}（稀疏=只埋核心 / 中等=主辅兼顾 / 密集=每条线索都呼应）{{/if}}

伏笔类型说明：
- 契诃夫之枪 / 预言暗示 / 象征伏笔 / 角色伏笔 / 对话伏笔 / 环境伏笔 /
  时间线伏笔 / 红鲱鱼 / 平行伏笔 / 回调伏笔（各附一句定义）

输出要求：
- 建议{{#if usesCount}} {{count}} {{/if}}{{#if notUsesCount}} 3-5 {{/if}}个伏笔
- 每个伏笔用 Markdown 格式
- 说明埋设方式和回收建议

[user]
小说名称：{{projectName}}
小说类型：{{genres}}{{#if worldContext}}

{{worldContext}}{{/if}}{{#if characters}}

【角色列表】
{{characters}}{{/if}}{{#if existingForeshadows}}

【已有伏笔】
{{existingForeshadows}}

请避免与已有伏笔重复，可以设计与它们呼应或交织的新伏笔。{{/if}}{{#if hasNoForeshadows}}

目前还没有设计伏笔，请根据世界观和角色设定建议初始伏笔方案。{{/if}}

请建议 3-5 个精心设计的伏笔，每个包含名称、类型、描述、埋设方式和回收建议。
````
可调参数：`density`（稀疏/中等/密集）、`count`（1-12）。

## context
世界观 + 角色列表 + 已有伏笔。

### 各个部分内容详细说明
- `worldContext`：世界观摘要块。
- `characters`：`buildCharacterContext()` 的角色分层输出（核心角色全信息、次要一句话、其他仅名字+阵营）。
- `existingForeshadows` / `hasNoForeshadows`：`foreshadows` 表现状，用于去重或初始建议分支。

# llm call · 角色完整设计

## 概要
- **name**: `character.generate`
- **role**: 角色设计大师 —— 创造有深度有弧光的角色
- **工作内容**: 基于世界观与已有角色，从零设计一个新角色的完整资料（姓名/定位/外貌/性格/背景/动机/能力/关系/弧光），写回 `characters` 集合。

## prompt

````text
[system]
````

本章大纲 + 前/后章摘要 + 世界观 + 角色列表 + 伏笔列表（把细纲和伏笔/角色 ID 硬绑定）。

### 各个部分内容详细说明
- `prevChapterSummary` / `nextChapterSummary`：前后章摘要，保证开场钩子与结尾悬念承上启下。
- `characterList` / `foreshadowList`：让模型输出**可回指的 ID**（`appearingCharacterIds` / `foreshadowIds`），供正文期一致性与伏笔看板复用。

# llm call · 情感节拍卡

## 概要
- **name**: emotion-beat-adapter（`emotion.beat`）
- **role**: 资深小说编辑 —— 分析与规划章节情感节奏
- **工作内容**: 写作前为本章生成"情感节拍卡"：3-6 个节拍，每拍含场景目标/情感基调/期望读者感受/角色变化 + 整章情感弧概述，输出 JSON。用于作者理清叙事节奏（EmotionBeatCard），不直接落正文。

## prompt

````text
[system]
你是一位资深小说编辑，擅长分析和规划章节的情感节奏。
你的任务是为即将创作的章节生成一份「情感节拍卡」，帮助作者在写作前理清叙事节奏。

要求：
1. 将章节拆分为 3~6 个关键节拍（如"开场铺垫"、"冲突升级"、"情感转折"、"高潮"、"余韵"等）
2. 每个节拍需要说明：场景目标、情感基调、期望读者感受、角色变化
3. 整体要形成完整的情感弧线（有起有伏）
4. 节拍之间要有情感的递进或反转，避免单调
5. 用简洁有力的语言

输出严格 JSON（不要 markdown 围栏）：
{ "overallArc":"整章情感概述（1-2句）",
  "beats":[ { "label","sceneGoal","emotionTone","readerFeeling","characterGrowth" } ] }

[user]
## 章节：{{chapterTitle}}
## 大纲摘要：{{chapterSummary}}
## 世界观背景：{{worldContext}}   # slice 1500
## 涉及角色：{{characterContext}} # slice 1000
## 上一章结尾：{{prevChapterEnding}}
请为该章节生成情感节拍卡。
````

## context
本章标题+大纲 + 世界观（≤1500）+ 涉及角色（≤1000）+ 上一章结尾。

### 各个部分内容详细说明
- 与 `detail.scene` 上下文近似，但产物是"情感节奏"而非"场景结构"，二者可并存（一层管情节结构、一层管情绪曲线）。

# llm call · 章节正文生成 ★核心

## 概要
- **name**: `chapter.content`（默认模板"内置-长篇连载"）
- **role**: 经验丰富的长篇连载作者
- **工作内容**: 把章纲 + 全部上游结构化上下文写成一章正文；`continuityMode: 'required'`，会在 user 末尾注入**连续性保护块**。产物经预览→采纳写回 `chapters.content`，并触发下游反写四层记忆。这是整条链的收敛点。

## prompt

````text
[system]  CHAPTER_SYSTEM
你是一位经验丰富的长篇连载作者{{#if usesTone}}，擅长写出{{tone}}风格{{/if}}{{#if usesPace}}、节奏{{pace}}{{/if}}的章节。

你的写作风格：
1. 开篇即抓人——第一段就要制造悬念或冲突
2. 善用对话推进剧情，对话自然有性格
3. 动作场面要有画面感
4. 每章结尾留钩子（伏笔/悬念/反转）
5. 文笔流畅，不用生硬的过渡

写作原则：
- 展示而非告知（Show, don't tell）
- 角色行为要符合其性格和动机
- 保持世界观一致性
- 注意前后文的连贯性{{#if worldRulesContext}}
- **世界规则约束**：涉及「📜取自真实」必须准确、不得时代错乱；「✨架空改造」尊重作者设定。{{/if}}

输出要求：
- 直接输出正文内容
- 不需要输出章节标题{{#if usesChapterLength}}
- 字数约 {{chapterLength}} 字/章{{/if}}

[user]
请根据以下信息写一章小说正文：

章节标题：{{chapterTitle}}
章节大纲：{{chapterSummary}}

世界观摘要：
{{worldContext}}

涉及角色：
{{characters}}

前一章结尾（衔接用）：
{{previousChapterEnding}}{{#if worldRulesContext}}
{{worldRulesContext}}{{/if}}{{#if userHint}}
用户额外要求：{{userHint}}{{/if}}

━━━ 末尾自动注入的「连续性保护块」（CONTINUITY_CORE_START … END）━━━
【本章任务与章纲】…
【直接前驱 handoff】…            # 上一章交接（finalScene/stateChanges/knowledge/commitments/openLoops…）
【前章实际进展与计划冲突】…      # planReconciliation 对账
【直接前驱真实 tail】…           # 前驱原文尾部
【当前世界最近 verified summaries】…
硬约束执行协议：先在内部逐项核对保护块中的事实/动作/禁令/人物限制；必须在正文前 40% 用明确可观察的行动逐项落实，不得只暗示、遗漏或改成相反行为。
篇幅纪律：优先完成本章任务终点与全部硬约束，再补氛围细节。
以上是最低连续性约束；不得用未来章或其他世界资料覆盖。
````
可调参数：`tone`（严肃/轻松/幽默/沉重/抒情/紧张/热血）、`pace`（慢/中/快/极快）、`chapterLength`（上限=所选模型最大输出）。

## context
一句话：**章纲 + 世界观 + 活跃角色 + 前驱衔接 + 世界规则 + 连续性保护块（四层记忆的读侧）**，经 `assembleContext` 分层预算装配后拼入。

### 各个部分内容详细说明
- `chapterTitle` / `chapterSummary`：本章任务锚点（outlineNode）。
- `worldContext`：`assembleContext` 装配的世界观/力量体系/词条等，且经 `sanitizeProseGenerationContext()` **剔除含"未来计划/尚未发生/异世界档案"标记的句子**（防剧透/串世界污染正文）。
- `characters`：活跃角色分层块（`filterActiveCharacters` 按当前章过滤已退场/未登场）。
- `previousChapterEnding`：当有连续性块时置为"（见文末连续性保护块）"，实际衔接信息走保护块。
- **连续性保护块**（`buildContinuityEnvelope`）：`L0` 不裁；由 `prepareContinuityContext` 按规范章序（`resolveCanonicalChapterSequence`）取直接前驱的 handoff / planReconciliation / 原文尾部 + 同世界最近已验证摘要；按 token 预算内部分配各段字数；附硬约束执行协议 + 篇幅纪律。
- `worldRulesContext`：真实与幻想规则（触发时代质感约束）。
- 另在 `ChapterEditor` 侧还会拼入题材上下文（genre）、文风上下文（`userStyleProfile`）。
- 装配后经 `analyzeContextSegments` 拆成带标签段喂 `ContextBudgetBar`——即"透明"的可见一半。

# llm call · 章节续写

## 概要
- **name**: `chapter.continue`
- **role**: 长篇连载作者（同 CHAPTER_SYSTEM）
- **工作内容**: 从已有正文末尾继续写约 1000-2000 字，保持风格与情节连贯；同样注入连续性保护块（含"当前正文续写锚点"= 已写正文尾部）。

## prompt

````text
[system]  CHAPTER_SYSTEM（同上）

[user]
请续写以下小说正文，保持风格和情节连贯：

章节大纲：{{chapterSummary}}

世界观摘要：
{{worldContext}}

已有正文（请从最后继续写，约 1000-2000 字）：
---
{{existingContent}}              # 取正文末尾约 3000 字
---{{#if userHint}}
用户额外要求：{{userHint}}{{/if}}

━━━ 末尾注入连续性保护块 ━━━
（同 chapter.content，额外含【当前正文续写锚点】= existingContent 末尾约 1600 字）
````
可调参数：`tone` / `pace` / `continueLength`。

## context
本章大纲 + 世界观 + **已有正文末尾** + 连续性保护块（含续写锚点）。

### 各个部分内容详细说明
- `existingContent`：当前章已写正文（截末尾 ~3000 字作展开上下文，另取末尾 ~1600 字作保护块里的"续写锚点"）。
- 其余上下文与 `chapter.content` 同源；`ChapterEditor.handleContinue` 会把角色上下文额外并入（`fullCtx` 默认不含角色时补上）。

---

## 附：链条关系速览

```
inspiration.reverse ─┐
story.generate ──────┼─→ worldview.dimension / rules.generate / world-group.*  (设定)
                     │        │
                     │        └─→ character.generate / .dimension / .supplement  (人物)
                     │                 │  relation.extract（正文↔关系）
                     ▼                 ▼
              outline.volume ─→ outline.chapter ─→ story-arc / plot.character-driven  (大纲)
                                        │
                                        ▼
                     detail.scene / 细纲增强 / emotion.beat   (节拍/细纲)
                                        │
                                        ▼
                            chapter.content / chapter.continue  (成文)
                                        │
                        （下游：反写四层记忆 + 提取 + 审校，见 D 正文，不在本清单）
```

上游产物通过 `context-builder` 格式化 + `assembleContext` 分层装配，成为下游每次调用的 `{{worldContext}}` / `{{characters}}` / `{{storyCore}}` / 连续性保护块等槽位——**这就是 StoryForge "编排靠固化 UI/流程、AI 只做单发 worker" 的落地方式**：没有 agent 决定"下一步调哪个"，是面板按钮 + 固定 adapter + 确定性上下文装配把这些单发调用串成一条链。
