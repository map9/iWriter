# 小说创作智能体系统：功能设计（v3）

## 1. 设计原则

1. **对话驱动**：所有功能入口都是自然对话，没有独立的表单界面
2. **作者管方向，agent 管执行**：作者判断好坏，agent 负责实现、维护、检查
3. **结构从写作中提炼**：StoryBible 是 agent 从写作和对话中提炼的，不是作者填写的
4. **Plan-first**：重要动作前先说打算，作者确认后再执行
5. **Diff 感知**：每次会话，agent 先了解文稿变化，再参与

---

## 2. 工作台

作者看到两个区域：

**编辑区**：文稿，可直接编辑。包含章节草稿和 agent 维护的 StoryBible 内容。

**对话区**：与 agent 的对话。agent 只在对话中出现，作者不需要时不出现。

---

## 3. 草稿管理

### 3.1 场景种子

作者可以随时写下任何程度的内容：

- 一句话：`"A 在雨中等人，但那个人不会来了"`
- 几个词：`"夜晚、车站、错过"`
- 一个问题：`"如果 B 在这里说了真话会怎样"`
- 一个情绪：`"那种明知道结果但还是要去做的感觉"`

不需要分类，不需要说明归属哪章。agent 记住这些种子，理解它们的情绪和意义，在合适时机引用或发展。

### 3.2 从种子到完整场景

agent 发展场景种子的方式：
- 在相关章节写作时自然融入，并告知作者
- 主动询问：`"你之前写的那个等人的场景，现在要展开了吗？"`
- 作者明确说要展开某个种子时，agent plan → 作者确认 → 执行

### 3.3 章节写作

标准流程：

```
作者给方向
  → agent 给 plan（打算怎么写、有什么选择）
  → 作者确认或调整
  → agent 执行
  → agent 完成后做一致性检查
  → 发现问题主动说出来
```

对于短小的局部改动（一段对话润色、一个词替换），可以跳过 plan 直接执行。

---

## 4. StoryBible 自动维护

StoryBible 是 agent 对项目当前状态的**理解摘要**，不是作者填写的资产库。

### 4.1 内容结构

```
【角色】
  每个已出现角色：
  当前状态 | 核心特质 | 性格缺陷 | 声音特征 | 所处弧光阶段 | 关键关系

【世界观】
  已确立的规则 | 关键设定 | 禁区 | 时间线重要事件

【故事状态】
  当前推进到哪里 | 已埋下待回收的伏笔 | 开放的冲突线索

【写作约束】
  叙事视角 | 时态 | 基调 | 风格特征

【待解决】
  agent 发现的矛盾 | 作者尚未确定的问题 | 悬而未决的设定
```

保持精简，目标 2000-4000 token，确保 agent 每次都能完整读取。

### 4.2 更新触发

- **对话中确认新设定**：agent 立即 patch 对应条目
- **每次写完内容后**：agent 检查是否有新信息需要更新
- **累积变化阈值**（新增/修改超过约 2000 字）：触发一次全面重读和重建
- **结构性变化**：人物核心设定改变、删除章节、时间线调整等，立即重建相关部分

### 4.3 作者与 StoryBible

- 作者随时可以查看
- 作者可以直接修改，修改优先级高于 agent 的理解
- 作者不需要主动管理它

---

## 5. 一致性检查

agent 在完成每一段写作后，在后台做一致性检查，发现问题主动提出。

**检查维度：**
- 角色行为是否符合 StoryBible 中已确立的性格和动机
- 有无叙事视角越界
- 时态是否一致
- 时间线是否自洽
- 有无违反已确立的世界规则
- 已埋下的伏笔是否有回收计划

**提出方式：**
- 轻微问题（风格层）：一句话带过，作者可以忽略
- 中等问题（人物/逻辑层）：写完后说明，给出修改建议
- 重要问题（结构/一致性层）：在执行前就提出，等作者决策

---

## 6. Plan-first 机制

以下情况 agent 先给 plan 再执行：

- 写一个新场景或章节
- 对已有内容做超过一段的改写
- 修改涉及已确立设定的内容（人物动机、时间线、世界规则）
- 结构性调整（删除、合并、重排章节）

**Plan 格式：**

```
我打算这样做：[具体说明写什么，怎么写]
考量：[为什么这样，有哪些权衡]
备选方向：[如果有其他路径，列出来]
继续吗？还是你有其他想法？
```

作者批准或编辑后的 plan 是后续写作执行的约束。Agent 在真正写入章节时必须显式承接批准后的版本，而不是重新按原始意图自由发挥。

---

## 7. Diff 感知会话启动

作者打开对话，agent 的第一个动作：

1. 获取文稿自上次会话后的变化
2. 读取 StoryBible
3. 必要时读取发生变化的章节或碎片文件
4. 对 StoryBible 做增量 patch（若能提炼出明确新事实）
5. 理解当前状态
6. 再回应作者

效果：agent 不会"不在状态"，不需要作者重新解释。

Phase 1 的 diff 能力先做到文件级：知道哪些文件新增、修改或删除。具体新增了哪几行、改了哪几段，不在 Phase 1 里承诺；如果作者追问具体变化，agent 通过重读相关文件总结当前内容。目标态的行级 diff 可在后续 git 集成或快照持久化中补齐。

---

## 8. 方向探索

作者面临方向选择时，agent 快速生成多个方向草图：
- 两个走向不同的后续场景
- 悲剧与治愈两种结局的对比草稿
- 不同视角下同一事件的效果

草图明确标记为探索内容，不自动变成正文。作者选定方向后，agent 将其发展为正式草稿（走 plan-first 流程）。

---

## 9. 碎片管理

作者随时可以写下任何碎片：一句对话、一个场景念头、一个人物细节、一个伏笔想法。

不需要分类，agent 自然理解其意义。在相关写作时，agent 主动引用或融入，并告知作者。

---

## 10. 版本管理

使用 git 原生版本控制：
- agent 完成一段重要写作后，建议 commit
- 重要节点（完成一章、完成初稿）用 tag 标记
- 方向探索在独立 branch 进行，探索完成后 merge 或 discard
- 不自研版本系统，直接用 git

---

## 11. 沉浸重入

作者重新打开搁置已久的项目时，agent 在做完 diff 检查后提供简短摘要：
- 上次写到哪里了
- 主要角色当前状态
- 有无悬而未决的问题或开放的伏笔
- 建议的下一步（2-3 个可直接点击启动的选项）

---

## 12. Skills 体系

Skills 是 agent 的内功，不是向作者暴露的功能入口。agent 在写作和审查时自动调用。

当前规划的核心 skills：
- `scene_structure`：分析和构建目标→冲突→结果的场景骨架
- `pov_craft`：叙事视角技法和一致性检查
- `character_voice`：角色声音辨识度分析和写作
- `pacing_sense`：节奏和张力感知
- `dialogue_craft`：对话真实性和角色声音
- `foreshadowing_tracker`：伏笔种植和回收追踪
- `reverse_outline`：从已有正文反向提炼结构
- `worldbuilding`：世界规则一致性维护

Skills 可持续补充，每增加一个 skill，agent 在对应维度的建议质量就提升一个层次。
