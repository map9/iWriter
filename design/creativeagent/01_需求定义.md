# 小说创作智能体系统：需求定义（v3）

## 1. 重新定位

本系统是一个**创作伙伴**，不是一个写作工具。

区别在于：工具等你知道要什么才能用，伙伴和你一起发现你要什么。

作者只做两件事：**写作**和**对话**。结构的建立、一致性的维护、资产的管理——全部由 agent 在内部完成，作者感知不到这些复杂性的存在。

---

## 2. 产品目标

支持作者从一个灵感出发，通过写作和对话，逐步发展成一部完整的小说。

这个过程不是线性的：边写、边改、边重构、边审核。某些想法开始只是一个点、一个场景、一句话，agent 不能"死"在那里等待完整信息，它需要有创作思维，能从模糊出发，帮助作者逐步看清方向。

---

## 3. 作者看到的

**只有两样东西：**

**文稿**：一个会生长的文档。内容包括：
- 章节草稿——从一句话的场景种子到完整章节
- agent 整理维护的角色/世界观/风格设定（作者可看可改）
- 待解决的开放问题

**对话**：和 agent 的对话界面。作者在这里给方向、接受或调整 agent 的建议、探索创作可能性。

作者不管理任何结构化数据，不填写任何表单。

---

## 4. Agent 的两种核心能力

### 4.1 Craft 知识（技法）

agent 深度理解写作技法，但不向作者暴露术语，而是用作者听得懂的语言提出建议：

- 场景结构：目标→冲突→转折/结果
- 叙事视角一致性
- 角色声音辨识度
- 节奏、张力与留白
- 伏笔与回收
- 对话真实性
- 类型规范知识

这些能力通过 skills 不断完善，是 agent 的内功。

### 4.2 创作直觉

- 从一个点延伸出多个可能方向，而不只是一种
- 发现作者没有注意到的主题共鸣
- 在给定方向后，想到"怎么写才好"而不只是"按要求写"
- 主动发现文稿中的潜在机会或矛盾

---

## 5. 核心需求

### 5.1 从任意起点开始

支持以下任何一种起点进入创作：
- 一句话场景描述、一种情绪、一个问题
- 一个人物的模糊想法
- 几个已经写好的散乱片段
- 一个"如果……会怎样"的假设

**不得**要求作者先完成完整的设定或大纲才能开始写作。

### 5.2 边写边构建

- 人物设定在写作和对话过程中逐渐清晰，agent 从中提炼并维护
- 世界观规则在写作中确立，agent 负责追踪一致性
- 大纲可以反向从已有内容生成，也可以预先规划，两种方式都支持

### 5.3 Plan-first，可控执行

agent 在做重要写作或修改前，先向作者说明：
- 打算怎么做
- 为什么这样做
- 有哪些备选方向

作者确认（或修改方向）后再执行。

### 5.4 长篇一致性保障

随着小说规模增长，agent 持续维护：
- 人物行为是否符合已确立的性格和动机
- 世界规则是否被遵守
- 视角/时态是否一致
- 伏笔是否有对应的回收
- 时间线是否自洽

### 5.5 Diff 感知的会话启动

作者打开对话时，agent 先检查文稿的变化，了解自上次会话后发生了什么，再参与讨论。作者不需要重新介绍情况。

### 5.6 写作流派中立

支持但不强制任何流程：
- 计划派：先讨论结构再写
- 直觉派：直接写，agent 帮整理结构
- 混合：随时切换

### 5.7 参与深度可调

- **深度共创**：agent 多提方案，少直接写，一起探讨
- **引导执行**：给定目标，agent 分解并执行，关键节点确认
- **方向探索**：快速生成多个方向草图，帮作者确认方向选择

---

## 6. 非目标

- 不让作者管理结构化数据（人物卡字段、提纲节点、YAML 表单）
- 不强制按系统流程工作
- 不是自动批量生成小说的系统
- 不把聊天记录作为唯一的长期记忆
- 不向作者暴露系统内部的技术概念（scene_type、block_id 等）
