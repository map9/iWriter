# 文档编辑工作流

先确定用户要改变什么，再读取足够证据，提交一个可审阅批次。回答、总结、分析和提供创意本身不授权写入。

## 判断修改尺度

| 尺度 | 判定 | 做法 |
| --- | --- | --- |
| 原子修改 | 一个现有块内的小型措辞、语法或标题修正，不改变块类型 | 读取目标块，提交一次修改，审批后结束 |
| 局部改写 | 一个局部章节或若干连续块，需要保持语气、结构或衔接 | 先读完整局部范围，再提交一个连贯批次 |
| 关联多点修改 | 同一术语、事实或设定在多处联动变化 | 先读所有受影响位置及必要上下文，再作为一个逻辑任务处理 |
| 大范围改写 | 全文改写、风格迁移或同一文件的大量修改 | 先让用户选择一次完成或分阶段批次 |

不能确定尺度时采用更保守的范围；连续性或一致性可能受影响时，不按原子修改处理。

## 执行顺序

1. 按主 prompt 的资源优先级确定目标文件与范围；目标仍不明确时询问。
2. 修改前读取目标内容和必要上下文。用户消息或当前工具结果已包含准确原文时不重复读取。
3. **REQUIRED SUB-SKILL:** 第一次块级写入或新建文档前加载 `document-block-tools`，并以其工具选择、内容格式、批处理和 ID 生命周期规则为准。
4. 按当前范围生成完整修改方案，一次提交当前审批批次，然后停止等待结果。
5. 原子修改审批后结束。局部改写、关联多点修改、删除和大范围改写在审批应用后读取一次受影响范围，检查衔接、事实一致性、旧表述残留和结构异常。

验证只用于检查。若发现还需修改，先说明问题，再提交新的受审批批次；不得把验证变成静默连续改写。

## 常见编辑意图

- 缩写、压缩、精简：默认保留关键信息并缩至原长度约三分之二。
- 扩写、展开、丰富：默认增加细节、例子或论证，扩至原长度约三分之五。
- 续写：从指定范围末尾继续；指定章节时续写一个章节，指定段落时续写一个段落。
- 修改、润色、校对、风格调整：保持用户未要求改变的事实、结构和语气。
- 删除：先读目标前后文，删除后必须检查衔接；需要相邻清理时放入同一修改批次。
- 总结、分析、创意：直接回答；只有用户要求插入、创建或落盘时才进入写入流程。

## 确认与分阶段

- 新建文档、大范围改写或删除前先确认范围；用户已经用“直接改”“直接删除”等明确命令给出授权时不重复确认。
- 大范围任务默认询问“一次完成”还是“分阶段”。用户要求直接执行时，先给出简短范围说明，再进入当前可安全承载的批次。
- 全文校对、语法检查或重写采用分段读取与编辑：完成当前章节或页面批次后等待审批；继续前重新读取最新结构与下一范围。
- 若一次完成会超出安全上下文容量，说明限制并切换为分阶段，不静默省略范围。

## 审批结果

- approved / edited：修改已应用；按修改尺度决定结束或执行一次验证读取。
- rejected：简短确认已跳过；不得自动重试相同或近似修改。说明其他已应用项，并询问用户下一步。
- failed to apply：这是应用失败，不是用户拒绝。刷新目标结构和内容后，只纠正一次；仍失败则报告错误和已尝试范围。
