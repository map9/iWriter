# context-discipline

Assembly comes **before** the work. Never form a judgment, an opinion, or a plan about existing material until you have read the minimum object set for the beat you are on and named the baseline you are judging against. A confident answer built on a partial read is worse than a slow one.

## 1. Priority order (settles every conflict)

1. **The author's current instruction > the workspace's current formal objects > history** (older versions, commits, candidate drafts).
2. **Confirmed premises > unconfirmed candidates.**
3. **Locally relevant > globally weak.**

Two consequences you must not soften:

- **Never let an older fact override a newer direction.** If the author just rewrote or committed something, that new text is the fact; an outline or setting that disagrees is the thing that is now out of date. Surface the conflict and its blast radius — do not "correct" the new material back toward the old object, and do not decide for the author.
- **Assembly precedes execution.** Do not generate content, opinions or fixes before the target objects are located and read.

## 2. Name the baseline, out loud

Before any comparison or review, state in one line: **what is being judged, and against what.** Typical baselines:

| What you are judging | Baseline |
| --- | --- |
| A draft the writer just produced | the confirmed chapter outline |
| A draft the author rewrote / just committed | **that draft itself** — outline and settings are downstream and may need to be updated |
| A candidate direction | `project.md` (theme, promise, scale) + the world's rules and forbidden zones |
| Two versions or two commits | the **later** one is the current fact; the earlier one is history |

If you cannot name the baseline, you are not ready to judge.

## 3. Minimum object set, by beat

Read this much before acting; expand only when the target is unclear, a reference is missing, a comparison or rollback is needed, or you must show a blast radius.

- **Diverge (opening options)** — `project.md`; the world's rules and **forbidden zones**; the current state of whatever the idea touches.
- **Compare (judging existing material)** — the material **in full**; its baseline (above); the reference objects it is judged against (characters on stage, the world rules it uses). Cross-chapter questions add the neighbouring chapters.
- **Converge (writing into an object)** — the confirmed upstream; characters on stage; neighbouring chapters for continuity; `project.md` for target length; the style object if one applies.

Reading rules:

- **Prose and any file that may carry the author's own notes: read it whole.** Buried details — a planted hint, an inline remark — are exactly what sampling loses.
- **Large index objects (the master outline) are read by targeted section, never dumped whole.**
- **Overview before detail**: get the shape first (heading tree, changed-file list), then pull only the parts you need.

## 4. Evidence laws

**Citation law.** Any claim that the text "violates", "contradicts" or "misses" an established fact must quote the establishing line from the object it comes from. If your quote does not actually support your claim, the quote wins and the claim is dropped. Asserting a violation that the source does not contain is the most expensive error you can make — the author may rewrite good material because of it.

**Search law.** The search tool matches **literal text, not patterns**: search one term at a time; never build alternations (`a|b`) or wildcards — they match nothing and return silently. **"No matches" is not evidence of absence.** Before concluding that something does not exist, re-query with a different single term or open the file and read. A negative search result may never be the sole basis for a conclusion.

**Stop law.** If a required object is missing, empty, or not in the state the work requires (an outline that is not confirmed, a character with no substance), **stop and say what is missing**. Propose filling the gap. Never invent the missing upstream and never push ahead on a guess.

## 5. What history is for

Commits, tags, changelog and older versions are tools for explaining, comparing, fixing a rollback point — they are **not** the source of current fact. Current fact is the working tree plus the author's current instruction. Never open a session with a global scan, an automatic diff, or a rebuilt summary; reach for history only when the task actually needs it, and read it by targeted range.
