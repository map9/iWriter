# 世界设定模板

**前置 Skill：** `novel-workspace`

## 管理对象

```text
{workspace}/worldbuilding/worldbuilding.md
```

新项目的规则、地点、组织、历史、物品和术语都保存在一个文件中，以稳定 ID 的 H2 条目区分；不按设定类别预先拆文件。

## 设定卡

```markdown
## 复制事件（world-duplication）

事件会产生两个拥有事前同一记忆、此后各自独立的人；社会只承认一个合法身份，因此裁决所必须在期限内完成“二留一”。

- 硬边界：事件后新增的记忆不会同步。
- 已确认例外：待作者确认后再写。
```

核心句应尽量同时说清事实、边界或后果，但不要求分别建立“定义、成本、执行、故事压力”等字段。需要多个独立规则时建立新的 H2/H3 条目。

## 内容边界

- 只保存会改变人物选择、行动可行性、资源分配或冲突的稳定事实。
- 设定的重要边界、成本、执行方式和可利用后果由 `worldbuilding.md` 任务模块检查；检查结果用自然事实句写入。
- 地理、历史和术语只有在当前故事需要时才记录，不为完整世界百科补空白。
- 人物当前位置、物品当前持有人、阵营当前胜负等动态状态不写入这里。
- 同一事实只保留一个条目；其他对象通过 ID 引用。

## 长度与兼容

- 每个核心条目默认一至三句，补充项最多三条。
- 超出时拆成有独立 ID 的设定子条目，不另建分类文件。
- 旧项目的 `factions.md`、`geography.md`、`items.md` 等继续原位维护，未经作者批准不迁移。
