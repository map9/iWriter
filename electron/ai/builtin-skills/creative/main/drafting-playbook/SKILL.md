# 正文撰写 Playbook

这是正文撰写阶段的主流程 Playbook。加载后接管本阶段的任务定位、上下文装配、授权、委托、质量验收与收尾。正文由 `writer` 写，正文质量由 `reviewer` 评；你不亲自写或评正文。

## 定位本轮写作任务

行动前确定：

- **类型**：只设计 beat / 新写一章 / 续写未完成正文 / 按明确范围重写；
- **目标**：章节文件与块范围；
- **终点**：本轮必须写到哪个事件、状态变化或章节终点；
- **约束**：必须实现、不得改变及可自由发挥的内容；
- **交付**：beat，或实际写入目标文件的正文。

作者只要评估或比较已有正文时转 `revision-playbook`。需要改变作品核心约定、人物、关系、故事线、总纲、卷纲、章纲或场景事实时转 `ideation-outline-playbook`。不要把设计问题交给正文执行者临场补写。

## 写作入口

写正文的硬前提是：目标章纲为 `confirmed`，且每个场景都能识别行动者的即时意图、会回应其办法的阻力、实际状态变化和下一条件。它们可以合并在一个场景因果句中，不要求出现固定字段名。

入口不满足就停止正文任务，指出具体缺口并转 `ideation-outline-playbook`；事件级总纲不能代替场景级章纲。beat 是可选写作层，不是入口替代品。

入口检查与正文取材分两层，避免主 agent 和 `writer` 重复读取：

1. 主 agent 只读取目标章纲中用于确认 `status`、目标场景因果和目标章节路径的块。路径使用“直读一次，窄探测回退”：已知或可由章号唯一得到的路径先直接读取；仅当读取失败或路径有歧义时，才对最窄父目录做一次定向探测。入口证据已经明确后，不再探测 `manuscript/`、`styles/`、`characters/`，也不加载正文模板或其他文件复核。
2. 作者批准写作后，主 agent 把路径、章/场景 ID、终点和约束交给 `writer`。以下正文取材由 `writer` 自读，主 agent 不预读、不转述：

- 目标章纲与目标章节；
- 直接相邻章节的衔接事实；
- 本章重要人物小传中与本场相关的目标、性格、关系、经历、能力、局限及说话/动作习惯，实际使用的设定事实，以及被引用的故事线阶段；
- 已启用的风格对象；
- 作者点名的外部材料或评审 findings。

不扫描全项目。集合对象的读取、路径回退和例外统一遵守 `context-discipline`；主 agent 只把已知路径和 ID 传给正文执行者，不通过目录读取重新发现，也不把整份对象或正文复制进委托说明。

## beat

先按作者要的交付处理：

- 作者只要 beat：由你设计并写进章文件，然后停止，交作者确认；不打开 write-session，不自动续写正文。
- 作者要正文：有 beat 就作为写作参考，没有 beat 就直接按已确认章纲写。

每个场景按需要设置 1–3 个粗 beat，记录因果动作或情感转向，不细化为逐动作填空。快节奏场景可以不设 beat。格式见 `manuscript-template`。

beat 的变更权限：

- 新建、单独增删、修改或重排 beat，由你完成。
- `writer` 可以在写作中轻微调整原位 beat，并报告调整。
- 未获本次明确授权，`writer` 不得增删或重排 beat。
- 你改动已有章节的 beat 后，说明对现有正文的影响；未经作者明确要求，不自动重写正文。

## 开启写作并委托

写正文前调用 `confirm_writing_plan`，`target_files` 传入目标章节路径。只在本轮确实会写正文时打开 write-session。

作者批准后，用 `task(subagent_type="writer")` 委托。`description` 必须包含完成本轮任务所需的输入：

- **章节**：目标章节路径；
- **创建还是修改**：从章纲创建、继续写，或修改指定范围；
- **目标范围与终点**：从哪里开始、在哪里结束，必须完成的叙事变化；
- **写作要求**：本轮目标、必须实现的事实和允许自由发挥的范围；
- **不可触碰项**：不得改变的正文、事实或结构；
- **参考对象**：必要的章纲、人物、设定、风格和相邻章节路径；
- **外部文件路径**：作者提供时附上；
- **评审 findings**：修订时附 `/large_tool_results/` 原始路径、选中 finding 和允许修改范围。

不要把项目对象内容转述进 `description`，也不要用笼统的“写得精彩”“更生动”代替目标、终点和约束。

每次委托返回后只判断一次固定状态并进入对应分支；不要在下一模型回合重新总结同一状态、重列同一计划或重复读取仍为 current 的范围。

## 处理正文执行者状态

只有 `DONE` 可以进入评审或收尾：

- `MISSING_FIELDS: ...`：从已确认输入补齐；无法补齐时询问作者。
- `NEEDS_MORE_CONTEXT: ...`：补充缺失的项目对象、外部文件或 findings 后重试。
- `NEEDS_PLAN_CHANGE: ...`：回到本 Skill 的 beat 路径，说明变更和正文影响；作者确认后修改 beat。
- `NEEDS_OUTLINE_CHANGE: ...`：转 `ideation-outline-playbook`；作者确认并更新上游设计后再回来。
- `DONE: ...`：本次委托已完成，可以进入质量检查。

非 `DONE` 不得进入评审、声称正文完成或调用 `finalize_chapter`。

## 成稿质量门

`writer` 返回 `DONE` 后，默认委托 `reviewer` 做一次章级 `developmental` 评审；只有作者明确要求跳过评审时才免。

评审输入包括：

- 审校范围：目标章节和必要块范围；
- 审校镜头：`developmental`，scope 为章级；
- 本轮写作目标、终点和不可触碰项；
- 已确认章纲及必要的项目对象；
- 需要版本比较时才提供比较基线；
- 作者提供的外部反馈。

要求正文评审者至少验证：

- 指定范围与叙事终点已经实际完成；
- 章纲中每个场景的行动、回应、转折和状态变化已经成为可观察的正文，而非概述；
- 人物行动符合其信息、既有关系、具体所求、可用办法与当前压力；
- 因果、时间、空间、资源、设定和前后衔接成立；
- 读者体验与本章功能相符，关键变化有足够叙事权重；
- 正文没有泄漏提纲字段、beat 标签、写作指令或分析语言。

必须读取 `reviewer` 返回的 findings 原始路径，不能只依据小结。逐条分流：

- 正文可在已授权范围内修复：把原始 findings 路径、选中 finding、对应块 ID、必要邻接块、修改范围和不可触碰项交给 `writer`，最多自动修订一轮。局部 finding 不把“全文”写成读取范围；只有章级 finding 才授权通读整章。
- 需要改 beat：回本 Skill 的 beat 路径。
- 需要改章纲或其他上游设计：转 `ideation-outline-playbook`。
- 需要作者做创作决定：说明问题、可选取舍及各自影响，由作者决定。

第二次 `writer` 返回仍按固定状态处理。若修订针对 `BLOCKING` 或 `MAJOR` finding，再委托 `reviewer` 做一次定向验证。验证输入列出修订后的目标块、必要邻接块和必须保持的结构锚点；只检查所选 finding 是否解决及这些位置是否引入直接回归，不把审校范围重新声明为全文，不启动新一轮全面评审，也不自动继续改稿。只有 finding 本身是章级问题，或局部证据无法验证终点/结构回归时才扩大范围。

验证未通过时，明确保留的问题和所需去向，不报告为已解决。临时 findings 留在会话结果目录，不自动写入工作区。

## 收尾与交付

本轮不再继续自动写作后，对已打开 write-session 的目标章调用 `finalize_chapter`，让作者整章 accept 或 rollback。

向作者只报告：

- 实际完成的章节与范围；
- 评审和定向验证结果；
- 正文执行者报告的 beat 调整；
- 尚未解决、需要改上游或由作者决定的事项。

作者要求的交付是正文时，实际正文修改必须已经存在；不能用写作计划、章节摘要、评审报告或“可以怎么写”代替。

## 红线

- 你不写正文，也不评正文；局部段落、评审失败或时间不足都不构成例外。
- 设计 beat 后不自动续写正文。
- 已有正文而作者未说明修改目标时，不猜测修改范围。
- 不让 `writer` 发明或静默改写上游故事事实。
- 非 `DONE` 状态不得进入评审或收尾；未通过验证的问题不得报告为已解决。
