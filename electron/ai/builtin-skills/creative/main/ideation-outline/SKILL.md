# 创意与提纲

负责正文之前的六类任务：立项、世界观、人物、总纲、卷纲、章纲。作者可以从任一任务进入或回到上游；你先判断当前任务和入口，再读取对应任务模块。

## 任务路由

从本 Skill 所在目录按需读取一个任务模块，不要一次加载全部：

| 作者要做的事 | 任务模块 |
| --- | --- |
| 从灵感起项目、确定 premise / 主题 / 读者承诺 / 篇幅 | `references/project-foundation.md` |
| 创建、补充或诊断故事依赖的世界规则、社会、地理、势力 | `references/worldbuilding.md` |
| 创建、补充或诊断角色与关系 | `references/character-design.md` |
| 设计或调整全书结构、主线与复线 | `references/master-outline.md` |
| 设计或调整某一卷 | `references/volume-outline.md` |
| 设计或调整某一章的场景级提纲 | `references/chapter-outline.md` |

一次请求跨多个对象时，先处理最上游的阻塞项；作者确认后再进入下一个任务。不要把六个模块拼成一次问卷或一次性生成整套小说。

## 入口与就绪

1. 缜密区分两件事：
   - **结构合法**：路径、标题、字段和固定令牌符合 `novel-workspace` 与目标 `*-template`。
   - **语义就绪**：已有内容能实际支撑下一任务。字段存在、填了“待确定”或写了空泛概括，都不算语义就绪。
2. 缺 `project.md` 时先进入立项。初始化所需的四个必需对象可以先创建骨架，但骨架存在不代表世界观、人物或总纲已经完成。
3. 进入总纲前，核心世界规则与主要人物关系须达到 `worldbuilding`、`character-design` 模块的最低验收。
4. 进入卷纲或章纲前，直接上游必须足以推出目标范围的结构功能与人物阶段。
5. 交给 `drafting` 的硬条件仍是目标 `ch{NNN}-outline.md` 为 `confirmed`，且场景的 goal / conflict / outcome 完整。

入口不满足就停止当前任务，明确指出阻塞项，切换到对应上游模块；不得用模型猜测补成正式事实。

## 通用工作循环

每个任务都按三步执行：

1. **诊断**：读取目标对象和直接上游，按任务模块的语义验收逐项判断“已确认 / 候选 / 缺失 / 冲突”。把缺口分为阻塞当前任务、可延后、写作中再定，并给出优先级判断。
2. **补充**：只对会改变作品方向的承重点给 2–3 个真正不同的候选。差异必须落在欲望、阻碍、代价、规则、人物选择或结局逻辑等承重轴，不以换人名、布景或术语冒充新方向。说明代价与推荐依据，作者决定。
3. **落定**：作者确认后，按 `novel-workspace` + 目标 `*-template` 写成事实。候选留在对话或 `exploration/`；没有确认不得进入正式对象。重开已确认上游前先报告下游影响面。

每轮只处理 2–4 个最承重的问题。能从已确认材料判断的不要反问；会改变创作意图的不得替作者决定。

## 最低能力与增强 Skill

六个任务模块包含完成任务所需的最低方法和验收；即使没有任何额外创作 Skill，也必须先把基础任务做完整。

只有出现以下任一信号时，才额外加载一个匹配的增强 Skill：

- 作者明确要求某题材或某维度更深入、更地道；
- 基础验收明确指出一个具体弱点，任务模块给出的基础修复仍不足；
- 已有候选同质化，需要专项方法打开新的承重轴。

按 Skill 的 description 匹配“适用信号 + 解决的问题 + 题材”，一次只解决一个已命名的弱点。增强 Skill 只能增加内容质量，不能改写阶段流程、对象 schema、作者权威或审批红线。应用后重新执行当前任务模块的最低验收。

## 交付

落盘前说明：

- 本轮确认了什么；
- 写入哪些对象与字段；
- 仍有哪些候选、缺口或冲突；
- 下一任务的入口是否满足。

字段格式、固定 ID、状态令牌和文件位置只看 `novel-workspace` 与对应 `*-template`，本 Skill 和任务模块不复制 schema。

## 红线

- 正式对象只写故事事实，不写“突出、弱化、不要描写、采用某技法”等给 writer 的指令。
- 不以字段数量、字数、角色数量、故事线数量、章节数量或场景数量替代语义验收。
- 不把网文、升级流、悬疑、仙侠等题材惯例当作全部小说的通用规则。
- 不替作者做创作决定，不把候选写成正式事实，不静默联动修改下游。
