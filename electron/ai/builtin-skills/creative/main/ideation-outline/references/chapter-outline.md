# 章纲任务

## 任务目标

把总纲或卷纲的结构任务下钻为可直接写作的场景链。章纲只写会发生什么、人物想要什么、受到什么阻力、局势如何改变；不写文风、措辞、镜头强调或给 writer 的指令。

## 输入与入口

必读：

- `project.md`；
- 对应的总纲节点和卷纲范围；
- 本章出场人物；
- 本章使用的世界规则；
- 相邻章节的入口/出口事实；
- 当前目标章纲。

直接上游必须能说明本章的结构功能、进入状态和目标结束状态。拆章时若仍要重新发明全书核心冲突，回总纲或卷纲任务。

## 工作流程

1. 用一句话定义本章的戏剧问题：谁想完成什么，什么力量使其不能按原计划完成。
2. 明确本章进入状态和离开状态；两者至少在处境、关系、认知、资源、承诺或风险之一发生变化。
3. 按需要设计场景，不预设数量。每个场景写清：
   - 进入场景时已有的状态；
   - POV 人物此刻可验证的短期目标；
   - 主动施压的冲突来源；
   - 迫使人物改变策略、选择或理解的转折；
   - 非顺利达成的结果；
   - 该结果给下一场或下一章造成的条件。
4. 检查人物行为能从其当前信息、欲望、恐惧和策略推出。
5. 安排信息释放：读者新知道什么、角色仍不知道什么、误解是否有事实依据。
6. 需要伏笔时，记录本章具体的埋设、强化或回收操作及预期回收位置。
7. 作者确认后将整份章纲 `status` 改为 `confirmed`；场景不设独立状态。

## 最低语义验收

- **可写性**：writer 不需要重新发明主要冲突、结果或 POV，就能把场景写成正文。
- **目标可验证**：场景结束时能判断人物目标是否达成，不能只写“了解情况、推进剧情、发生交流”。
- **冲突主动**：阻力会回应人物策略，不只是天气不好、心情复杂或单方面拖延。
- **转折存在**：场景中至少发生一次改变策略、权力、关系或理解的转折。
- **结果改变状态**：outcome 是未达成、带代价达成、或达成后暴露新问题；不能无代价顺利完成。
- **因果交接**：下一场因上一场的决定或结果而发生。若任意调换场景仍无影响，因果链需要重做。
- **场景必要**：删除场景会损失人物选择、因果变化、关键信息或情感兑现；只损失背景说明的场景应合并或删除。
- **章节变化**：本章结束后至少一个承重状态发生变化，并对下一章形成具体压力或期待。
- **事实纯度**：scenes 中没有“重点描写、不要强调、语言要克制、制造爽感”等写作工单。

## 增强 Skill

- 场景顺利、冲突靠误会或因果松散：可加载 `scene-and-plot-construction`。
- 人物选择不可信：可加载 `character-believability`。
- 悬疑题材的线索与回收需要深化：可加载 `suspense-foreshadow`。
- 题材 Skill 只能增强场景事实，不得写入文风或生成指令。
