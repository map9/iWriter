# 人物任务

## 任务目标

建立能主动选择、能彼此施压、能在故事中发生可信变化的人物。人物深度来自压力下的决策逻辑，不来自标签、履历长度或角色数量。

## 输入与入口

必读：

- `project.md`；
- 人物真正依赖的世界规则；
- `characters/characters.md` 和目标个人档案；
- 已存在时，直接相关的总纲节点或正文事实。

先从 narrative-engine 判断故事需要哪些功能和关系，再决定角色数量。不要按预计字数机械增加角色。

## 工作流程

1. 明确每个主要人物在叙事机器中的功能，以及没有此人时故事会缺少什么压力。
2. 建立人物决策链：
   - 他真正想得到或守住什么；
   - 他最怕失去、暴露或再次经历什么；
   - 什么错误认知让他反复采用有代价的策略；
   - 他通常怎样争取、回避、控制、交换或攻击；
   - 优点与缺陷如何来自同一根源；
   - 什么底线一旦被逼近，就必须作出暴露人物本质的选择。
3. 对核心关系分别写 A 如何理解 B、B 如何理解 A，以及双方此刻各想从对方得到什么。关系冲突应由真实利益和心理结构产生。
4. 规划弧光时使用“初始策略 → 递增测试 → 触发事件 → 有代价的选择 → 不可逆变化”，不把遭遇事件本身当成人物成长。
5. 用至少两个不同压力情境测试角色；如果换成另一角色仍会做同样的事，继续深化决策逻辑。
6. 重要角色写个人档案；短暂角色留在登记表。作者确认后再落盘。

## 最低语义验收

- **专属性**：能从人物事实推出至少两个可见动作、台词策略或回避方式；不能只得到“他很矛盾、很善良、很坚强”。
- **能动性**：主要人物会主动追求、隐瞒、交换、拒绝或破坏，不只承担剧情通知。
- **压力一致**：行为能沿“压力 → 解读 → 决定 → 行动 → 后果”推导，不能只用“剧情需要”解释。
- **关系发动机**：核心关系双方的欲望、恐惧或利益会自然相撞；若一次坦诚对话即可永久解决，必须确认这是否是作者有意设计。
- **对抗逻辑**：对抗方拥有自洽的目标、利益或运行逻辑。可以残酷，但不能只有“因为邪恶”这一层。
- **弧光因果**：每次变化都有触发、选择和代价；角色不是被事件拖到目标状态。
- **弧光差异**：多个角色不会用同一种成长模板；交汇点会互相改变选择或代价。
- **世界一致**：身份、能力、行动空间和价值观与世界规则、阶层及经历相容。

增加背景和字数不能替代任何一项验收。

## 增强 Skill

- 行为像剧情方便、角色标签化：可加载 `character-believability`。
- 多个角色起点和结局已确定、需要编织中间弧光：加载弧光/群像专项 Skill；它只补弧光节点和交汇，不接管整个总纲流程。
- 特定题材要求独有身份、修行或伦理结构时，加载对应题材 Skill。
