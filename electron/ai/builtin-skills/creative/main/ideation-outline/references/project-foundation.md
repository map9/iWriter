# 立项任务

## 任务目标

把作者的灵感核转成能持续生长的作品基础，并在确认后建立必需对象。立项不是一次生成完整世界与大纲，而是确定后续创作所依赖的核心承重关系。

## 输入与入口

最低输入是一句话、一个意象、一种人物处境或一种情感方向。已有 `project.md` 时先读它和作者点名的相关对象。

先保留作者提供的：

- 核心意象、人物处境或最想保留的事件；
- 希望读者获得的主要体验；
- 明确不想写成什么；
- 已确定的题材、篇幅或叙事形式。

缺失时可以给候选，但不得把你的偏好写成作者意图。

## 工作流程

1. 从灵感核提取“谁被什么压力逼到必须行动”。
2. 建立核心链：
   - 主角当前状态与可行动目标；
   - 会主动回应主角的对抗力量或系统；
   - 失败、成功和不行动各自可能失去什么；
   - 主角或核心关系将发生什么不可轻易回退的变化；
   - 故事如何反复产生事件、选择、升级、揭示或悬念；
   - 这些选择共同逼问什么可争论的主题问题；
   - 作品持续向目标读者兑现什么体验。
3. 若存在多个可行方向，候选必须在目标、对抗机制、代价或结局逻辑上分叉。
4. 用下方验收诊断薄弱处；只修最承重的缺口。
5. 作者确认后写 `project.md`。首次初始化同时按模板创建：
   - `worldbuilding/worldbuilding.md`；
   - `characters/characters.md`；
   - `outline/master-outline.md`，`status` 为 `draft`。
6. 世界观和人物文件可以写入本轮已确认的初始事实；未知必选字段使用本地化待定占位符。骨架存在不代表通过后续任务入口。

## 最低语义验收

- **作者保真**：premise 仍能识别出作者最初的核心意象或情感方向；若发生转向，转向已由作者明确确认。
- **行动性**：主角不是只等待事件；压力到来后必须采取会引发回应的行动。
- **对抗性**：阻碍有自身目标、利益或运行逻辑，会针对主角的行动作出反应；不依赖一个偶然误会维持全书。
- **代价三面**：失败、成功、不行动至少两种结果存在真实损失或取舍。
- **发动机测试**：不追加全新巧合，当前设定能自然推出至少三种性质不同的后续压力或两难；若只能重复同一种冲突，发动机未成立。
- **主题落地**：主题是可争论的问题，至少两个立场都有成立理由，不能用一句正确口号回答。
- **承诺一致**：premise、theme、reader-promise、core-change、narrative-engine 指向同一部作品，没有各说各话。
- **规模可行**：预期字数、章节与故事发动机相称；短故事不被迫堆复线，长故事也不能只靠重复升级撑篇幅。

任一失败都要给出具体诊断与修复候选，不用增加字数掩盖。

## 增强 Skill

- 灵感只有题材默认答案、候选只是换皮：可加载 `direction-ideation`。
- 作者要求特定题材的核心承诺或发动机：加载对应题材 Skill，但只增强当前基础链。
- 主题无法落实为人物选择：可加载 `thematic-coherence`。

增强结果仍须通过全部最低验收。
