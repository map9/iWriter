# outline-review

The developmental-editor read: does the story hold up, and how to make it hold up better. Read the whole at once — character, structure, causality, theme are interdependent; a character problem is often a structure problem.

## Input objects

A one-line-story expansion · short/long synopsis · story proposal · full/volume outline · chapter list & summaries · character system · world/setting · narrative-strategy plan · a revised outline. (Pure idea divergence → `idea-review`; finished prose → the drafting-stage chapter review.)

## Review goal

Judge current viability and find the most-worth-fixing problem for the next round: is the core goal/conflict clear; are events driven by character choice; do conflict/stakes/cost escalate; is character change earned; do mainline/subplots/chapters progress clearly; do climax and ending pay off the opening promise; what is the ROOT cause; in what order to revise.

## Review scale

Strong: core conflict · protagonist goal/choice/change · causal chain between key events · mainline/subplot organization · chapter/phase function · pacing/turns/climax/ending · how theme lands through action. Light: positioning-vs-story fit · world rules supporting plot · genre-promise payoff · gross continuity. None: sentence quality · dialogue wording · rhetoric · punctuation/format · not-yet-written prose. (Outline brevity is not "lacking description".)

## Internal frame (check silently; never output point-by-point)

The six dimensions at outline emphasis — positioning (mid) · story mechanism (strong) · character system (strong) · narrative organization (strong) · expression (weak) · integrity (weak). Craft pulled as needed: `structural-pacing-diagnosis`, `character-believability`, `scene-and-plot-construction`, `thematic-coherence`.

## Procedure (internal)

Identify the story model (who / wants / obstacle / cost / start / key choices / final change) → build the main causal chain (each node "because → therefore", not "and then") → check character drive (acting vs. reacting; clues always handed in; turns always coincidence) → check escalation → check structure & pacing → check arc & theme → find the ROOT (one root explaining several symptoms; output the root, then its effects) → form revision options.

## Output shape (natural-language editor's letter; no JSON, no dimension dump, no chapter-by-chapter recap)

- **Overall judgment** — basically viable?; most valuable part; the single most core problem; what this round fixes.
- **Worth keeping** — 2–4 effective designs; why; what not to damage in revision.
- **Core problems** — 3–5, by priority: symptom / root cause / impact / revision goal.
- **Revision options** — per problem: object / direction / resulting effect / what else it touches; when several paths, option A/B with benefit & cost, then a recommendation.
- **Revision order** — dependency-ordered; don't fix locals a later structural change will overturn.
- **Done-criteria** — 3–6 verifiable checks generated from this review.
- **Author's calls** — only genuine author-intent decisions; say how each changes the story. Omit if none.

## Stop condition

Stop when the author knows what to fix first, why, and to what degree. Advise, don't adjudicate; never emit a full replacement outline. An agreed change goes to `outline-authoring` (or `worldbuilding-authoring`) with its approval.
