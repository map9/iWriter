# 世界观任务模块

## 目标

建立故事依赖的规则、制度、空间、历史、物品和资源关系。设定必须约束人物选择，并能在正文中被看见。

## 输入

按任务读取 `project.md` 的相关故事约定、`worldbuilding/worldbuilding.md` 的目标设定块，以及直接受影响的人物、故事线或场景。先取目标 ID，不整读设定集合。

## 工作方法

对每项承重设定，在内部检查：

1. 它实际允许、禁止或迫使什么发生。
2. 适用边界、成本、例外或违反后果是什么。
3. 谁维护、执行、垄断、利用或绕开它，人物会实际遇到什么程序。
4. 空间、交通、资源、物品或社会位置怎样提供和限制行动。
5. 普通人如何接触它；正文能呈现哪些动作、用语、物件、痕迹或感官标记。
6. 它会在哪个具体人物处境中被使用、违反或验证。

按类型补足承重点：

- 规则或技术：触发、能力、限制、成本、例外和痕迹；
- 制度或组织：权力来源、资源、程序、内部限制和公众接触面；
- 地点：空间关系、出入、交通、控制者、行动条件和感官特征；
- 历史或习俗：仍在生效的结果、群体记忆、利益归属和行为边界；
- 物品或术语：使用条件、保管、准确含义及误用后果。

检查设定之间的漏洞、二阶影响和矛盾；一条记录只保留会改变故事或正文表现的结果。

## 最低语义验收

- **故事必要**：删除该设定会改变冲突、行动办法或事件可行性。
- **有边界**：规则不能只在剧情方便时开启；关键例外有来源和代价。
- **能运行**：制度、禁令和资源分配能说明为何持续有效，不靠“所有人都遵守”。
- **可被人物使用**：人物可以顺从、利用、绕开或反抗，设定因此进入选择。
- **有具体后果**：至少能指出一个人物处境，说明谁获益、谁受损或谁被迫改变办法。
- **可见**：正文可以通过行动、程序、空间、物件、语言或感官细节呈现，不依赖说明段。
- **可执行**：地点、资源和技术给出的行动条件足以支持场景调度。
- **内部一致**：与已确认规则、时间、资源和社会关系相容。

## 交付与落盘

按 `worldbuilding-template` 交付。简单设定使用核心句和最多三条补充；承重设定按需保留边界、运作、空间、人和程序、可写表现，每条合并成直接事实句。

作者明确要求落盘时，将稳定事实写入 `worldbuilding/worldbuilding.md` 的唯一条目；未归位设想留在卡片，动态剧情状态留在章纲或正文。
