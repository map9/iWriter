# 立项任务模块

## 任务目标

把作者的灵感核转成能持续生长的作品基础，并在确认后建立必需对象。立项不是一次生成完整世界与大纲，而是确定后续创作所依赖的核心承重关系。

## 输入与入口

最低输入是一句话、一个意象、一种人物处境或一种情感方向。已有 `project.md` 时先读 `work`、`story`、`constraints` 中与本轮有关的块，以及作者点名的相关对象。

先保留作者提供的：

- 核心意象、人物处境或最想保留的事件；
- 希望读者获得的主要体验；
- 明确不想写成什么；
- 已确定的题材、篇幅或叙事形式。

缺失时可以给候选，但不得把你的偏好写成作者意图。

## 工作流程

按作者要求执行理解、生成、评估、修复、比较或转录。生成与修复时：

1. 从灵感核提取“谁被什么压力逼到必须行动”。
2. 在内部建立核心链：
   - 主角当前状态与可行动目标；
   - 会主动回应主角的对抗力量或系统；
   - 失败、成功和不行动各自可能失去什么；
   - 主角或核心关系将发生什么不可轻易回退的变化；
   - 故事如何反复产生事件、选择、升级、揭示或悬念；
   - 这些选择共同逼问什么可争论的主题问题；
   - 作品持续向目标读者兑现什么体验。
   这些是语义检查，不是七个交付字段；相互一致时压缩成 `story` 的一至三句。
3. 只有任务需要方向选择时才给候选；候选必须在目标、对抗机制、代价或结局逻辑上分叉。
4. 用下方验收诊断薄弱处；只修最承重的缺口。
5. 作者明确要求落盘后写 `project.md`。首次初始化同时创建只有 H1 和本轮已确认内容的：
   - `worldbuilding/worldbuilding.md`；
   - `characters/characters.md`；
   - `outline/master-outline.md`，`status` 为 `draft`。
6. `storylines.md` 和 `materials/cards.md` 只有出现已确认故事线或需保存的未归位想法时才创建。世界观和人物文件可以写入本轮已确认的初始事实；未知内容直接省略，不建立待定字段。骨架存在不代表通过后续任务入口。

## 最低语义验收

- **作者保真**：核心故事约定仍能识别出作者最初的意象、处境或情感方向；若发生转向，转向已由作者明确确认。
- **行动性**：主角不是只等待事件；压力到来后必须采取会引发回应的行动。
- **对抗性**：阻碍有自身目标、利益或运行逻辑，会针对主角的行动作出反应；不依赖一个偶然误会维持全书。
- **代价三面**：失败、成功、不行动至少两种结果存在真实损失或取舍。
- **发动机测试**：不追加全新巧合，当前设定能自然推出至少三种性质不同的后续压力或两难；若只能重复同一种冲突，发动机未成立。
- **主题落地**：主题是可争论的问题，至少两个立场都有成立理由，不能用一句正确口号回答。
- **整体一致**：人物处境、持续冲突、核心变化、主题问题和读者体验指向同一部作品，没有各说各话。
- **规模可行**：预期字数、章节与故事发动机相称；短故事不被迫堆复线，长故事也不能只靠重复升级撑篇幅。

任一失败都要给出具体诊断与修复候选，不用增加字数掩盖。

## 交付形态

完整立项成果至少让作者能直接判断以下内容是否是他要写的作品：

- 一至三句核心故事约定与人物处境；
- 主角行动、对抗回应和后果继续升级的持续机制；
- 失败、成功或不行动所包含的真实取舍；
- 预期的不可逆变化与可争论的主题问题；
- 持续兑现给目标读者的体验；
- 与预期篇幅相称的结构规模。

不要用题材标签、气氛描述、卖点口号或字段清单代替这条核心链，也不要把上述六项机械排成分析报告。作者只问其中一个问题时，只交付该问题所需内容；写入 `project.md` 时按 `work`、`story`、`constraints` 压缩。
