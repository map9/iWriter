# 评估、比较与修复模块

## 用途

本模块与目标创作维度模块一起使用。它负责编辑判断、逻辑检验和修复纪律，不取代项目、世界、人物、故事线或提纲的具体方法。

## 先确定评判任务

把作者的问题归入一种主结果：

- **判断**：某个设计是否成立、哪里成立或不成立；
- **诊断**：问题的表现、根因与影响；
- **比较**：多个版本在同一目标下谁更合适、代价是什么；
- **修复**：在保留明确约束的前提下交付修改后的内容；
- **验证**：检查一次修改是否真正解决原问题、是否制造新问题。

作者只问判断或原因时，不自动扩展为候选生成。作者要修复时，不能停在建议清单。

## 证据与基线

1. 用作者当前要求定义本轮目标和不可触碰项。
2. 用工作区正式对象定义已确认事实。
3. 只把作者指定的旧版本作为比较基线，不让旧版本覆盖当前意图。
4. 把正文证据分为“明确发生或表现”“合理推断”“尚无依据”，不把推断写成事实。
5. 先以最强、最合理的方式还原现有方案，再评判；不通过曲解制造问题。

## 编辑检验

按问题选择必要检验，不机械输出整张清单：

- **直接可行性**：数量、票数、权限、资源、身体能力、时间、空间、信息与先后顺序是否允许。
- **更直接行动**：人物是否已有更合法、更低成本、更符合目标的行动；若有，现方案为何仍会发生。
- **因果必要性**：关键结果是否来自此前的决定与回应；删除新增巧合、临时规则或便利人物后是否仍成立。
- **人物可信度**：行动是否符合人物所知、所求、所怕、惯用策略和当前压力。
- **对抗有效性**：阻力是否会主动回应，是否拥有自身利益或运行逻辑。
- **叙事功能**：该设计是否真正改变选择、关系、认知、资源、风险或读者期待。
- **尺度与完整性**：交付物是否处在作者要求的层级，是否包含该层级成立所需的完整变化。
- **连续性**：是否与已确认设定、前后结构和已写正文矛盾。

优先寻找能解释多个表面问题的根因。不要用增加角色、事件、场景、设定或字数掩盖一个基础逻辑缺口。

## 输出方式

### 判断或诊断

1. 先给明确结论；
2. 给决定结论的事实或因果；
3. 指出根因和影响范围；
4. 只有存在真实不确定性时才说明缺失证据。

### 比较

1. 先声明共同目标与比较标准；
2. 分别说明各版本改变了什么、解决了什么、牺牲了什么；
3. 给出结论及适用条件；
4. 不用个人偏好、辞藻多少或信息量大小代替比较标准。

### 修复

1. 列出必须保留的已确认约束；
2. 找到能够解决根因的最小改动；
3. 交付修订后的实际人物设计、故事线、结构节点、场景链或其他目标内容；
4. 说明必要的连带影响，不自动修改；
5. 重新执行目标维度模块的最低语义验收。

### 验证

针对原问题逐项核对修改结果，并检查新引入的事实、行动和结构是否产生新的矛盾。没有解决时明确报告失败点，不把“更丰富”“更完整”当作已修复。

## 停止条件

满足作者本轮要求的判断、比较、修复或验证后停止。未被请求的后续发散、落盘或跨阶段改写，不作为默认追加动作。
