# 故事线任务模块

## 目标

设计或修复一条能独立发展的变化线。故事线可以是外部目标、关系、人物变化、悬念、资源或权力变化；它不是总纲字段，也不必先有总纲。

## 输入

按任务读取 `project.md` 的相关故事约定、`storylines.md` 的目标线块、直接相关的人物和世界事实，以及作者点名的章纲、正文、起点、终点、保留事件和否决方向。缺失信息只有在会改变这条线的推动力、终点或核心取舍时才阻塞。

## 尺度

- 人物设定解释“为什么会这样做”；故事线记录“行动与回应怎样持续改变状态”。
- 总纲安排多条线在全书中的顺序和交汇；故事线本身先独立成立。
- 一个事件念头尚未形成因果变化时先放卡片，不硬扩成故事线。

## 工作方法

1. 用一句话确定谁在推动、什么状态将怎样改变，以及这条线最终要回答或兑现什么。
2. 找到推动者会采取的第一步，以及人物、制度或现实条件为何必须回应。
3. 每个阶段用一个因果句完成：行动 → 回应 → 实际变化 → 新条件。不要把四项拆成字段。
4. 后一阶段必须改变办法、代价、理解、关系、资源或风险，不能重复同一种摩擦。
5. 以有代价的选择、兑现、失败、转化或有意开放结束。
6. 多线交织时，只记录会实质改变另一条线行动、资源、认知、时机或代价的交汇；具体结构位置交给总纲。

## 最低语义验收

- **持续推动**：有行动主体，不靠作者不断投放无关事件续命。
- **双向响应**：行动会引发人物、关系、制度或世界的具体回应。
- **阶段变化**：每一阶段都改变承重状态，使下一步不能原样重复。
- **因果必要**：主要阶段能用“因此 / 但是”连接；交换或删除会改变后续。
- **选择与代价**：关键变化含人物选择及其代价，不把遭遇本身当成长。
- **独立成立**：移出总纲仍能说清自身起点、发展和兑现。
- **交汇有效**：被标为交汇的节点确实改变另一条线，而非同场出现。

## 交付与落盘

默认交付一个核心句和按因果排列的一行式阶段。不要另列“功能、推动者、戏剧问题、对抗来源、变化路径、闭合方式”六个字段；这些语义应由核心句和阶段自然体现。

作者明确要求落盘时写入单一 `storylines.md`。总纲、卷纲和章纲只引用 `line-*` / `beat-*`，不复制完整故事线。
