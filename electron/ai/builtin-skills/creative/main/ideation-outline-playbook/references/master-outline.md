# 总纲任务模块

## 目标

把已确认的作品约定、人物压力、世界规则和独立故事线安排成全书因果骨架。总纲负责“何时发生、怎样交汇、为何进入下一段”，不重新拥有这些上游事实。

## 输入

按当前范围读取 `project.md`、承重人物与世界块、`storylines.md` 中会进入总纲的故事线/阶段、当前总纲目标块，以及作者指定的结局或必须保留事件。不要整读无关集合。

入口最低要求：核心冲突能持续产生回应；主要人物有可推导的行动；关键规则界定可行性与代价；需要进入总纲的故事线已能独立成立。缺口回对应任务，不用事件数量掩盖。

## 工作方法

1. 明确全书开端状态、核心扰动、最终不可逆变化和结局后的新状态。
2. 选取真正改变全局走向或多线关系的结构节点，不把每章摘要抬升为节点。
3. 每个节点用一个因果段合并：谁基于当前信息作出什么决定，对方或世界怎样回应，什么状态不可逆地改变，由此出现什么代价、揭示或下一压力。
4. 用引用标明该节点推进或交汇的 `line-*` / `beat-*`；不复制故事线内容。
5. 让升级改变损失、约束、时间、关系、信息、道德代价或不可逆性中的必要维度，不只是敌人变强。
6. 主题和人物变化通过节点中的实际选择及后果体现；不另建重复的主题节拍和人物弧光摘要。
7. 伏笔的真实事实仍归人物、世界或故事线；未归位线索归卡片；总纲只在必要时引用预计兑现节点。

## 最低语义验收

- 节点主要能用“因此 / 但是”连接，不是“然后”列表。
- 关键转折至少部分由人物决定触发，不全靠巧合、命令或外部袭击。
- 中段迫使人物改变办法、目标理解或代价判断。
- 高潮由此前的选择、关系、规则和故事线推进推出，不靠新能力或便利人物解围。
- 每条进入总纲的复线至少一次改变其他线的行动、资源、认知、时机或代价。
- 结局兑现核心问题和读者体验，并展示变化后的具体状态。
- 目标节点可以继续下钻为卷或章任务，无需重新发明核心冲突。

## 交付与落盘

默认交付开端、按因果排列的结构节点和结局状态。每个节点一个短因果段；不重复输出完整人物档案、世界规则或故事线。

作者只要设计一条故事线时使用 `story-design.md`；只有要求安排全书结构时才写总纲。落盘后未获作者确认保持 `draft`。
