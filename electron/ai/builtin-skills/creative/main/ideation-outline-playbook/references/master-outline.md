# 总纲任务模块

## 任务目标

把已确认的作品基础、人物压力和世界规则组织成全书因果骨架。总纲回答“为什么下一段必然由上一段长出”，不是事件清单，也不是章节级场景表。

## 输入与入口

必读：

- `project.md`；
- 直接承重的世界规则；
- 主要人物档案与核心关系；
- 当前 `outline/master-outline.md`；
- 作者指定的结局、结构或必须保留事件。

入口最低要求：

- narrative-engine 能持续产生对抗；
- 主角与至少一个核心关系或对抗力量具备可推导的决策逻辑；
- 核心规则足以界定什么可行、什么有代价；
- 主题能够落到人物选择。

不足时回对应上游任务，不用事件数量掩盖。

## 工作流程

按作者要求执行理解、生成、评估、修复、比较或转录。生成与修复时：

1. 明确全书开端状态、核心扰动、最终不可逆变化和结局后的新状态。
2. 为主线和必要复线分别确定：
   - 由谁推动；
   - 要解决的戏剧问题；
   - 对抗来源；
   - 变化路径；
   - 与主线发生不可替代作用的交汇点；
   - 如何闭合或有意保持开放。
3. 建立结构节点。每个节点写清：
   - 进入节点时的状态；
   - 人物基于当前信息作出的决定；
   - 对抗方或世界作出的回应；
   - 造成的不可逆变化；
   - 人物付出的代价或获得的揭示；
   - 由此产生的下一重压力。
4. 让升级发生在至少两个维度，例如风险、损失、时间压力、关系撕裂、信息不对称、道德妥协或选择不可逆性；不要只把敌人变强。
5. 把主题放进数次有代价的选择及其后果；把主要人物弧光安排到会彼此改变的节点。
6. 伏笔在总纲只记录作用和大致揭示节点；具体埋、强、收写入相应章纲。
7. 作者明确要求落盘后写入模板；未完成确认时保持 `draft`。

## 最低语义验收

- **因果链**：节点之间主要能用“因此 / 但是”连接，而不是连续使用“然后”。
- **人物发动**：主要转折至少有一部分由人物决定触发；不是所有变化都来自巧合、命令或外部袭击。
- **策略变化**：中段迫使主角改变目标理解、策略或代价判断；不能只是重复早期冲突。
- **升级有效**：后续节点带来新的损失、约束或不可逆性，不是换地点重复同一种障碍。
- **高潮必然**：高潮由此前累积的选择、关系和规则推出，并要求主角作出与 core-change、theme 相关的决定；不能靠未铺垫能力或新人物解围。
- **复线必要**：每条复线至少一次改变主线的选择、资源、认知或代价；否则合并或删除。短作品允许没有复线。
- **弧光交汇**：主要人物不是各走各的成长线，关键交汇会改变彼此的行动。
- **结局兑现**：结局回应核心戏剧问题和 reader-promise，同时展示变化后的具体状态。
- **可下钻**：目标范围的结构节点能继续拆成卷或章的戏剧任务，而不需要重新发明核心冲突。

## 交付形态

全书总纲应交付：

- 开端状态、核心扰动、最终不可逆变化和结局后的新状态；
- 主线及必要复线各自的推动者、戏剧问题、变化路径和闭合方式；
- 按因果排列的结构节点，每个节点包含人物决定、对抗回应、状态变化、代价或揭示及下一重压力；
- 故事线交汇、人物弧光转向和主题选择的结构位置；
- 高潮如何由此前选择、关系和规则推出并兑现读者承诺。

总纲保持全书因果骨架的尺度，不展开成章节摘要合集。作者只要求一条故事线时先用 `story-design.md`；只有任务要求把它放进全书结构时，才映射为总纲节点。
