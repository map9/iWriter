# context-discipline

在判断、比较或修改既有材料前，先读够完成当前任务所需的最小上下文。不要把权威、比较基线和评判标准混成一个概念。

## 1. 三个不同概念

### 权威：什么可以决定当前工作

优先级固定为：

1. 作者当前明确指令和本轮已确认输入。
2. 工作区当前正式对象。
3. 历史版本、提交和候选材料。

已确认内容高于未确认候选。作者刚改过的文本是当前版本，但不自动获得改写章纲、人物或设定的授权。若作者意图不清，且冲突会改变事实，指出冲突和影响范围并询问；不要自动覆盖任一方。

### 比较基线：从哪里看变化

基线只用于版本比较，不决定谁有权。

- 单稿评审：可以没有比较基线。
- 两个版本或两个提交：较早版本是比较基线，较晚版本是目标。
- 作者改过的正文：需要说明变化时，以改动前版本为比较基线。
- writer 新写的草稿：只有要求比较前后变化时，才使用写作前版本或会话快照作为基线。

### 评判标准：用什么判断好坏或是否成立

评判标准来自作者当前明确要求、已确认章纲、`project.md`、相关人物与设定、适用的 style 等正式对象。标准可能与目标文本冲突；此时按权威顺序处理，不能把“比较基线”冒充标准。

## 2. 最小上下文

按任务读取，不做无目的全局扫描：

- **评审或比较**：完整读取目标范围；有比较任务时读取基线；再读取直接相关的评判标准。跨章问题才增加相邻章节。
- **委托评审**：主 agent 只需读够形成完整输入信息；实际执行者必须完整读取目标范围、基线和评判标准。
- **写作或修改**：读取目标章纲、承重人物的行动/关系/表现/能力边界、实际使用设定的边界/运作/空间/程序/可写表现、相关故事线块、连续性所需的相邻正文，以及 `project.md` 的相关约定和适用 style。
- **单文件集合**：`characters.md`、`worldbuilding.md`、`storylines.md`、`cards.md` 先看结构，再按稳定 ID 取目标块；不得因为只有一个文件就整份灌入上下文。
- **可能包含作者批注的正文**：在声明范围内完整读取，不能抽样。

已读到唯一事实源后，不再读取其派生摘要、变更记录或其他文件中的同义转述。先解析直接引用；只有目标不清、引用缺失、事实冲突、需要比较/回滚或分析真实影响范围时，才扩大到第二跳。

当前会话已经包含、来源明确且未被文件修改的内容可以直接使用，不为了“新鲜”重复读取。向 subagent 委托时优先传目标、范围、约束和文件路径，让执行者按需读取，不复制整份项目对象。

## 3. 证据纪律

### 引用

声称文本“违反”“矛盾”或“遗漏”某项既有事实时，必须引用确立该事实的原文。引用不支持判断时，撤回判断。

### 搜索

搜索默认按字面匹配，只有 `a|b|c` 表示 or。用材料自身的文件名、标题和措辞组织查询；同义词和混合语言表达尽量合并查询。零结果不是“不存在”的证据：换用材料中的实际措辞重查，或直接打开相关文件。

### 停止条件

必需对象缺失、为空或状态不满足任务要求时，停止并说明缺口。不得猜测缺失的上游内容。

## 4. 历史材料

提交、标签、变更记录和旧版本只用于解释变化、比较或确定回滚点，不是当前事实的默认来源。只有任务需要时才读取，并限制在相关范围。
